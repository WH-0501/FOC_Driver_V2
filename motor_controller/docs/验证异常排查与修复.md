# 验证异常排查与修复

## 实机反馈与结论边界

用户反馈断开调试器重新上电后仍有异常：Uq 对齐显示成功，但纯 Ud 验证结束超时，时间轴仅约数百毫秒，电流环不能转动。不能将这一现象直接归因为调试器预启用 DWT，也不能宣布电流环问题已解决。

逐项对比新增验证前保存的源码与当前源码，原有校准函数保持一致；新增内容为验证函数及 board.h 包含。验证不写 direction、offset 或极对数，但会驱动电机、调用现有故障保护，并在结束时失能、清除电流 PID。若保护锁存故障，之后的使能会被拒绝，因此它并非对硬件状态完全无影响。

截图当前采用 Uq；此前成功截图采用 Ud。两者“对齐后电角”分别接近 0° 与 270°符合现有代码定义，不能直接比较这一个字段。零偏差异、验证偏差约 21°以及不能转动仍需排查，不能简单解释为方法不同就正常。

## 本轮修复

1. DWT 初始化无论跟踪标志原来是否开启，都设置频率换算系数、使能周期计数。保留正在运行的计数器，不在重复初始化时清零。旧代码在 TRCENA 已置位时提前返回，即使是其他初始化路径置位，也可能留下零系数。这是代码可确认的缺陷，不是本次实机根因的确认。
2. 延时按短块执行，使用无符号周期差处理计数回绕；需要时恢复 DWT 初始化。避免绝对截止值比较的跨越问题。
3. 验证每次要求的 5 ms 等待，用独立板载定时器检查至少经过 4 ms。若没有达到，返回 ERR_TIMEOUT 并失能，不继续扫角或报告成功。该检查同时能暴露定时器与 DWT 时基不一致，但不会单凭错误码区分二者。
4. 结束应答在失能后有限重试最多 5 次、间隔 2 ms。实际 CAN 发送使用单个 PTB，写锁占用时会返回失败；旧代码忽略最终发送失败，确实可能出现最后采样已到而最终结果丢失。
5. GUI 默认选 Ud，与此前成功流程一致；仍保留其他方法。运行时若收到样本但没有结束应答，会明确显示样本数和缺少结束应答，不再一概暗示固件不支持。
6. GUI 增加完整时间检查：完整的 9 点验证最后时间必须至少 7 秒，数百毫秒的压缩轨迹不能被判为通过。

本轮不更改校准公式、不替用户改电流环增益或电流极性，也不清除保护故障以强行驱动。

## 验证

- DWT 实际源代码配合寄存器模拟：跟踪预开启、计数器未开启、重复初始化保持计数值、零系数恢复、5 ms/700 ms 等待、32 位回绕测试通过。
- 校准/验证回归通过，新增“延时失效时不发送采样、失能并返回超时”测试。
- GUI 19 项测试通过，新增压缩时间不能通过的测试。
- 58 个 ARM 目标文件完整编译链接通过。没有执行烧录或实机验证。

后续需要区分：仅重新上电并做 Ud 对齐就不能转，还是执行验证后才不能转。后一种情况首先读取结束错误码与运行状态中的锁存故障；前一种情况需要结合给定 Iq、反馈 Id/Iq、控制模式和故障状态继续检查电流闭环。


## 用户复测澄清与验证通讯补丁

用户确认此前误选 Uq；改用 Ud 后校准成功且电流环可运行。因此电流环不能转动不再作为新增验证功能已造成回归的证据。当前剩余问题为验证只收到部分采样、缺少最终结果。GUI 默认已设为 Ud，并增加自动化断言。

采样帧与结束应答统一使用 PTB 有限重试：最多 5 次，失败间隔 2 ms。单次写锁忙不再直接中止；持续失败仍返回通讯错误并退出。即时成功、短暂忙恢复及持续失败退出的实际 C 辅助函数回归通过，58 个 ARM 对象完整构建通过。该补丁未改动校准、电流环算法；是否解决实机验证超时仍需复测。截图的旧超时文字说明运行中的 GUI 尚未包含更新，需关闭后从当前工程重新启动。
