# C06：控制模式能力与执行一致性优化

## 1. 问题与结论

本地项目：`D:\workspaces\code-registories\FOC\FOC_Driver_V2\motor_controller`。

原 `control_mode_needs_pwm()` 将 CST、CSV、CSP、MIT、HOMING、电压模式及多种开环模式视为可输出 PWM，但 `foc_control_run()` 只有四个实际控制分支。枚举已定义不等于算法已实现。

原 CAN 设置模式有失能检查，因此不能断言 CAN 原来可以直接在正常运行中随意切模式。实际缺口是：未实现模式可通过选择和使能检查；直接调用模式 API 缺少状态验证；执行默认分支不主动关闭旧输出。

本次统一能力定义、入口准入、使能和执行分派，并增加运行时关断兜底。没有把尚未实现的模式简单映射成其他模式来假装支持。

## 2. 唯一能力定义

在 `control_mode.h` 中新增 `control_mode_executor()`。支持判断、PWM 需求判断及 FOC 分派都从该映射得到执行类型。

| 模式 | 当前行为 |
|---|---|
| IDLE | 支持停机，不输出 PWM |
| TORQUE | 支持现有 Iq 电流闭环；尚不代表 N·m 转矩换算已实现 |
| SPEED | 支持现有速度闭环 |
| POSITION | 支持现有位置闭环 |
| SPEED_OPEN_LOOP | 支持现有速度开环 |
| CSP、CSV、CST、MIT、HOMING、TORQUE_OPEN_LOOP、POSITION_OPEN_LOOP、VOLTAGE | 明确拒绝 |
| RESERVED、越界值、负数非法值 | 明确拒绝 |

以后添加控制器，需要同时提供执行类型和分派分支，不能只将枚举加入 PWM 需求名单。位置环限幅量纲、速度／电流限幅和其他独立问题不因模式获准运行而自动得到解决。

## 3. 接口及状态约束

`mc_set_ctrl_mode()` 从 `void` 改为返回 `error_t`：

- 不支持的模式：`ERR_CTRL_MODE`，保留原模式、原状态和有效控制输出。
- 非 IDLE 模式切换：要求 `STATE_IDLE` 且硬件已失能；成功后清除四个 PID 状态，再发布新模式。
- `STATE_RUNNING` 即使尚未实际 arm，也不允许切换到另一运行模式，返回 `ERR_STATE`。
- 标定期间返回 `ERR_CALIBRATING`；故障状态返回 `ERR_FAULT_LATCHED`。
- IDLE 请求通过现有 `mc_disable()` 执行停机；成功后记录 IDLE。标定中的取消行为仍遵循现有 `mc_disable()` 返回值。
- 该接口面向前台调用，不应在电流环 ISR 调用。正常运行换模式采用“失能 → 选择模式 → 设置目标 → 使能”的顺序。

拒绝一个非法模式请求与检测到内部非法运行模式不同：前者保持有效运行，后者必须关闭输出。

`mc_enable()` 和 `foc_fsm_request_running()` 继续共用 PWM 需求判断，现在只接受真正有执行器的四种运行模式。

没有清除给定值字段，也没有实现运动中的无扰模式切换；重新使能前应显式确认新模式的给定值，避免沿用旧目标。

## 4. 运行兜底与非阻塞停机

在 `foc_control_loop()` 开始处检查运行模式，先于传感器 I/O 和可能的 FSM 使能动作：

```text
STATE_RUNNING
   ├─ 合法运行模式：继续采样、状态机和控制执行
   ├─ IDLE：关闭输出，转入 STATE_IDLE
   └─ 未实现／非法模式：关闭输出，锁存 FAULT_PARAM，转入 STATE_FAULT
```

FOC 分派默认分支及 FSM 的 RUNNING 路径也有防御检查。默认分支不再无操作返回，让旧 PWM 一直保留。软件检查在下一次正常控制调用时执行，不替代独立硬件保护，也不能覆盖 CPU 停止运行的故障。

发现并修正停机路径中的阻塞风险：`motor_driver_disarm()` 原来在停止 PWM 后调用 `gate_driver_exit_sleep()`；MP6540 若处于休眠，该调用会等待唤醒时间。

本次将普通 disarm 改为：停止 PWM → 关闭所有相位 EN → 清除 armed；保持当前休眠状态，不执行唤醒等待。后续显式 arm 流程仍负责驱动器唤醒。没有将带休眠延迟的 shutdown 路径放进新兜底。

## 5. CAN 协议行为

保留控制模式命令 `0x41` 和原有模式枚举数值，设置模式仍使用一个模式字节。

以前越界模式会映射为 IDLE；现在保留收到的数值并交给统一 API 验证，避免非法输入被静默解释成另一个合法模式。

该命令新增同命令码的一字节结果回复：

| 返回值 | 含义 |
|---|---|
| `ERR_NONE` | 设置／停机成功 |
| `ERR_CTRL_MODE` | 未实现或非法模式 |
| `ERR_STATE` | 尚未停机或硬件仍使能 |
| `ERR_CALIBRATING` | 当前标定不允许普通模式切换 |
| `ERR_FAULT_LATCHED` | 故障锁存 |
| `ERR_PARAM` | 缺少模式字节 |

这是一个新增 ACK 行为；客户端不应把结果字节当作模式回显。固件项目内唯一模式设置调用点已更新。现有 Python GUI 仍可能列出所有枚举，本次未修改 GUI；选择未实现模式会由固件拒绝。GUI 后续可过滤选项并展示 ACK，但不是固件有效控制的前提。
