# 设备端电流环辨识：快速多正弦与逐频正弦

## 当前固件入口（2026-11-20）

当前模块化固件默认 `FOC_SWEEP_ENABLED=0`，请求设备扫频会明确返回 error=3。需要设备测试时全局定义 `FOC_SWEEP_ENABLED=1` 全量重编译，再由界面发送 `0xBC` 启动；编译开启不会自动注入。普通 PID/调制内没有扫频钩子。实现、RAM 和耗时验证以 [固件优化记录](../../motor_controller/docs/SWEEP_OPTIMIZATION.md) 为准；下文带日期的旧时序修复章节为历史背景。

当前固件的状态前 20 字节兼容 v1，诊断版返回 40 字节有效负载，包含 A5/A6 revision=1 的间隔、失败样本和分段耗时；DLC 尾部填充允许存在。默认关闭版返回 20 字节和 error=3。该错误会提示使用诊断固件，不自动降级为主机发波。

## 使用与范围

更新配套应用固件后，在“数据分析 → 扫频 / 带宽测试”选择设备模式。需要 V2、CST 已使能、目标电流为零，并确认测试工作区。不会自动使能、修改 PID、关闭保护或增大测试电流。

建议首次板上验证先使用逐频小幅值并检查时序；确认后可使用 20–2000 Hz、16 个频点的快速法定位趋势，再点击“转逐频精测”设置交点附近频段。测试完成会清零失能；精测需重新确认并使能后手动开始。若无交点，不能外推带宽；若相干性不足，不能把曲线当成有效环路模型。

| 特性 | 快速多正弦 | 逐频正弦 |
|---|---|---|
| 范围 | 20–2000 Hz，20 Hz 栅格 | 20–2000 Hz，按采样周期量化 |
| 点数 | 3–16，互不重复 | 3–16，互不重复 |
| 激励 | 同时叠加各频率正弦，Schroeder 相位分布 | 单频正弦，逐个频点执行 |
| 稳定时间 | 一个 50 ms 周期 | 至少 20 ms 且至少 4 个完整周期 |
| 测量 | 三个 50 ms 周期，分别估计谱 | 四段，每段 4 个完整周期 |
| 采集时间 | 20 kHz 下 4000 点，共 200 ms，含稳定段 | 随频率变化；默认 16 点原生模型测试约 3.87 s |
| 用途 | 快速定位趋势与带宽所在区间 | 提高交点附近频率密度与测量稳定性 |

200 ms 是 MCU 激励/采集时长，不含初始化、配置确认、CAN 频点读取、GUI 刷新。它也不是连续频带任意分辨率扫描：50 ms 分段对应 20 Hz 栅格，当前最多 16 个被激励的离散频点。界面分别显示设备采集时间和主机完整耗时。窄频段频点不足时拒绝参数，不悄悄重复频率。起始频率高于 40 Hz 时，设备自动保留 20 Hz、40 Hz 两个低频基准，其余点布置在请求频段内（此时至少 4 点）；避免窄带精测把已衰减的点误当成直流平台而高估带宽。

幅值为**总激励的峰值上限**，0.005–0.5 A，且不能大于配置 Iq 限值的 80%。多正弦会在启动前计算一个完整周期的合成峰值并归一化，故每个频率的输入幅值小于总峰值。提高频点数会分摊每条谱线的能量。弱信号优先用逐频法复测；不会自动提高电流。

## 测量路径与算法

MCU 在现有 20 kHz FOC 周期内生成目标，在同一周期读取 `state.i_q`（与电流控制器相同的实际反馈），不使用 CAN/主机接收时间。参考更新与采样反馈的离散时间关系保留，结果包含真实采样、计算、PWM、反馈滤波及电机动态，不能与连续理想模型直接等同。

每个激励频率用递推正交振荡器产生正弦/余弦，并累积反馈的复数投影；当前固件在前台预计算各段相同的精确输入谱。所有采集段为完整周期；频点实际 Hz 由设备回传，不能用请求 Hz 替代。ISR 不执行三角函数、FFT、文件写入或 CAN 发送，不保存完整 20 kHz 时序。

对各段的复数输入 X 和反馈 Y 计算：

- `Sxx = Σ |X|²`，`Syy = Σ |Y|²`，`Syx = Σ Y·conj(X)`。
- `H1 = Syx/Sxx`；增益为 `20 log10 |H1|`，相位为 `arg(H1)`。
- 相干性 `γ² = |Syx|²/(Sxx·Syy)`。当前显示门限为 γ² ≥0.90、至少 3 段、有效输入和响应幅值。

相干性来自多段谱平均，**不是正弦拟合 R²**。只有三段的快速结果仍有统计不确定性；高相干性也不能单独证明系统线性或无系统误差。应通过逐频、重复测量及不同小幅值的一致性确认交点。不同测量电流下的结果不可无条件合并。

带宽沿用相对低频平台的首次 −3 dB 交点，并显示插值所在区间；前两点需平坦，不能跨越无效频点。不从闭环 `Iq给定→Iq反馈` 直接虚构开环增益裕度或相位裕度。本次未增加自动电机参数辨识或自动 PID 改写。

## 实时与保护

- 单次启动后自行执行有限时长测试，无续租。上位机的 `0xBD` 仅查询，不生成或刷新激励。
- 禁止在非 CST、未使能、故障或非零目标下启动；升级期间不允许启动。
- 外部 `0x03` 或组合指令中的电流给定会中止辨识，不与激励叠加。
- Iq 限幅、软限速、q 轴 PID 输出限幅、q 轴输出 ramp 介入或 PWM 矢量缩放，标记为失效并停止。
- 保留已有硬超速、过流、温度、母线等保护。失能、故障和模式变化撤销激励。
- 对当前 20 kHz 硬件，采样 ISR 间隔应为 40–60 μs，测量到的 FOC ISR 主体耗时不得超过 45 μs；异常时中止并报告时序标志。耗时不包含中断函数外层所有指令，不能代替示波器/WCET 验证。45 μs 为检测阈值，不是实测性能承诺。
- 完成或中止后停止注入、给定清零并失能；不会清除锁存故障后自动重启。

## 自定义 CAN-FD 扩展 v1

所有整数和 IEEE754 float32 均大端。以下为去掉 CNT/CMD 后的有效负载，允许 CAN-FD DLC 的尾部填充。模式值不改变旧协议。会话号与频点索引用于拒绝陈旧结果。

### 0xBC 启动/停止

请求 11 字节：`version:u8=1, action:u8(0停止/1多正弦/2逐频), run:u16, lowHz:u16, highHz:u16, count:u8, peak_mA:u16`。

### 0xBD 查询状态

空请求。与 0xBC 共用 20 字节状态应答：

`version:u8, error:u8, state:u8, method:u8, run:u16, count:u8, progress:u8, fs:u32, acquiredSamples:u32, flags:u16, maxIsr_us:u16`。

state：0空闲、1采集、2完成、3中止。error：0成功、1忙/状态不允许、2参数错误、3功能未编译。flags：1状态或停止，2限制介入，4时序/执行耗时异常，8竞争电流指令。正常完成 flags=0。

### 0xBE 读取频点

请求：`run:u16, index:u8`。仅采集完成后读取，读取不会消耗结果。应答 34 字节：

`version:u8, error:u8, run:u16, index:u8, state:u8, flags:u16, hz:f32, inputAmplitude:f32, outputAmplitude:f32, H1real:f32, H1imag:f32, coherence:f32, averages:u16`。

状态与结果都必须收到专用应答；0x7E 分发 ACK 不是测试完成依据。旧固件不支持时超时并停止，不自动回退成主机逐点发波。

导出 CSV 使用明确的 `h1_gain_db, coherence, averages` 列及来源说明文件。设备模式只返回频域累积结果，没有原始时序 CSV；主机低频模式与已有原始样本导入功能保留。

## 参考与取舍

- [NXP MCAT](https://www.nxp.com/design/design-center/software/automotive-software/motor-control-application-tuning-mcat-tool:MCATSW)：区分电机参数估计、控制器整定与实时调试。本实现只覆盖实测电流闭环频响。
- [Elmo Sine Sweep](https://www.elmomc.com/capabilities/servo-technology/special-functionality/sine-sweep-emulation/)：逐频施加正弦并分析响应，配置激励电流与运动限制。未在所查官方页面确认“任意全频段 200 ms”精度承诺；本实现的 200 ms 是上述离散多正弦方案的明确采集预算。
- [Beckhoff Bode Plot 属性](https://infosys.beckhoff.com/content/1033/te132x_tc3_bodeplot/956354443.html)：参考频段/频点、给定和反馈可视化、激励幅值与跟踪约束的分离，未照搬其驱动专用协议。
- [Microchip Current Loop Tuning](https://microchiptech.github.io/mcaf-doc/9.0.2/algorithms/foc/tuning.html)：区分控制器设计目标、采样/PWM 影响与实际环路响应，不能把理论 800 Hz 当作测得值。

## 验证和交付边界

原生 C 测试使用真实 `sweep_engine.c` 对 800 Hz 离散一阶对象验证两种模式，幅值误差小于 0.15 dB、相位误差小于 0.03 rad；校验 200 ms 样本数、合成峰值上界、参数拒绝、中止和低相干性噪声。协议/FOC 集成测试覆盖 DLC 填充、状态准入、ISR 注入、竞争给定和停止。

上位机 Demo 使用明确的 800 Hz 模型模拟设备应答，仅验证界面/协议流程，不代表真机性能。需同时升级固件和上位机。尚未在真机测量新增算法的 ISR 最坏耗时、信噪比或实际电流环带宽；若报告 flags=4，先检查采样周期及执行耗时，不绕过检查。

## 2026-11-05 时序中止修复

现场日志：设备接受启动，仅记录 1 个样本后 flags=0x4，旧应答最长耗时为 0。该日志不能确定实际周期偏差值。

BC/BD 状态保留原 20 字节前缀，增加：偏移 20/22/24 为最小/最大/最近周期 u16，26 为原因（1 周期间隔、2 执行超时），27 为扩展标记 0xA5，28 为首次异常样本计数 u32，均大端。新界面在中止时先刷新数据再显示原因，兼容旧 20 字节应答。

需同时更新本目录 MotorTune.exe 和 firmware/AX58400_AT32M416_APP.efw。原生算法、FOC/协议、DWT 测试及 Qt 9/9 回归通过。尚未刷写真机，实际最坏执行耗时与带宽待硬件验证。
