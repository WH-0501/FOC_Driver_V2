# CST 实现与 PT/TORQUE 差异（2026-11-05）

## 本工程的命名和边界

当前固件没有单独的 `PT` 枚举。本文以原有 `CTRL_MODE_TORQUE = 1`（上位机 TORQUE）作为用户所称 PT 的对照。它目前是直接 Iq 控制，不是带转矩斜坡规划的完整 Profile Torque 实现。

本次实现 `CTRL_MODE_CST = 6`：在自定义 CAN-FD V2 协议下，由上层周期发送 Iq，固件每个 FOC 控制周期使用最新给定。没有增加 CANopen CiA 402 状态机、同步 PDO、分布式时钟或 SYNC 锁存。已有 `0x00 SYNC` 命令不作为本实现的目标生效边界。CST 名称表示本工程的周期给定模式，不表示完整的标准协议一致性认证。

## 实现差异

| 项目 | 现有 PT/TORQUE | 本次 CST |
|---|---|---|
| 模式值 | 1 | 6 |
| 使用方式 | 单次目标或上层自行更新 | 上层周期更新目标，适用于扫频等连续给定 |
| 输入及单位 | `0x03` Iq，int16 大端，1 mA/LSB | 相同，未改变帧格式 |
| 目标存储 | `ref.iq`，A | 相同，最新给定覆盖旧值 |
| 控制环 | d/q 电流环，Id=0，不经过位置/速度 PID | 相同 |
| 目标生效 | 解析写入后，随后电流环周期读取 | 相同，无等待 SYNC/插值/主机定时器回调 |
| 无新目标 | 保持最后目标，受既有保护约束 | 相同；不新增续租，也不因一个发送周期缺包立即失能 |
| 转矩轨迹规划 | 未实现 PT 输入斜坡规划 | 不增加输入轨迹规划 |
| 电流/速度保护 | Iq 限幅、软限速、硬超速等 | 复用同一条保护和电流环路径 |
| 模式切换 | 失能后允许；运行/标定/故障时拒绝 | 相同，切换时清 PID 状态 |
| B5/B6 限速回读 | 返回用户 Iq、限制后 Iq、介入标志 | 已补齐相同字段，模式值仍为 6 |
| B9 调试 | 上层原始 Iq 给定，电流环活动标志 | 已补齐活动标志，仍报告上层给定，不用软限速修改后的值替代 |
| BA/BB 调试 | 外环不执行 | 相同，不误报速度/位置环执行 |

两种模式共享算法，切到 CST **不会自行提升电流环带宽或消除通信延迟**。已有电流 PID 的输出限幅、积分限幅及输出 ramp 配置仍有效；“无输入轨迹规划”不等于移除了这些 PID 行为。

实现位置：`APP/control_mode.h` 模式准入与 PWM 资格；`APP/FOC/foc.c` 调度；`APP/comm/protocol/custom/can_fd_custom.c` 限速和 PID 回传；`APP/datatypes.h` 模式注释。HMI 的限速快照也已识别 V2 CST 为电流控制模式。

## V2 操作顺序

1. 失能后发送 `CNT 41 06`，检查 `0x41` 专用应答，确认模式为 CST。
2. 给定清零：Node 1 示例 `CNT 03 01 00 00`；确认工作条件后使能 `CNT 40 01`。
3. 周期电流示例：+0.200 A 为 `CNT 03 01 00 C8`，−0.200 A 为 `CNT 03 01 FF 38`。CNT 依现有规则递增。协议 ACK 仅证明分发，不代表电流已到目标。
4. 正常遥测验证实际 Iq；精确环路分析使用设备 PID 调试时间。停止实验清零并失能。

模式值以 V2 为准；旧版协议和旧版 Python 上位机未改动。CST 完成后，上位机低频扫频可通过原有 CST 检查，但它仍是主机低频端到端测试；本次未增加设备内部高速扫频信号源。

## 验证与交付

- 控制模式回归：全枚举准入、使能和执行路径；CST 正负给定、重复周期保持、最新值更新、电流限幅、软限速、制动电流、原始给定保留、运行切模拒绝、硬超速锁存。
- PID 协议回归：CST 电流环活动位有效，速度环不活动，B9 原始给定保持正确；持久调试订阅和采样状态上报回归通过。
- 命令 ACK 队列回归通过。HMI 运动控制、扫频算法回归通过。
- ARM Compiler 5 全量编译链接 58 个对象，生成 AXF/HEX/BIN。保留现有 6 条编译警告（标定不可达语句、保护函数声明、未使用函数/变量），未以本次改动掩盖。
- 应用镜像链接地址 `0x08001000`，沿用现有 bootloader 布局；交付的是应用镜像，不是 bootloader。
