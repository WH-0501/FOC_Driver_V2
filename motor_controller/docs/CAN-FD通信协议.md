CAN-FD 仲裁段 1Mbps，数据段 5Mbps

本文档 **CMD 表与字段语义以 V2.0.0 为准**（本仓库 `motor_controller` FOC 固件）。与旧 dex-con / 灵巧手等设备通信时需选用 **V1.0.0** 语义，见下文「协议版本」。

# 协议格式

| ID      | Count | Command | Data1~N | 协议填充 |
| ------- | ----- | ------- | ------- | ---- |
| Node ID | CNT   | CMD     | DATA    | 00   |

> 正常情况下，电机端仲裁段只会过滤三个 ID：0x00、自身 ID、IAP 的 0x7FF

- Node ID: CAN-FD ID 地址， **0x00 表示广播**
- CNT: 帧计数
- CMD: 功能码
- DATA: 有效数据域
- 协议填充: CAN-FD 数据长度为（0~8、12、16、20、24、32、48、64），数据长度不足时补充 0x00

## 协议版本 V1.0.0 与 V2.0.0

两代协议 **帧壳相同**（`[CNT, CMD, DATA…]`，Node-ID 在仲裁段），**功能码 CMD 基本一致**；差异在若干数据域的 **物理单位、枚举线值、状态/错误字节解析**。上位机需显式选择版本（如 `motor_controller_gui` 连接面板），不可混用。

| 项目                                     | V1.0.0                                  | V2.0.0（本文档 / 当前 FOC）                                                                                                                                            |
| -------------------------------------- | --------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 位置 Q7（`0x01`、周期上报等）                    | 单位 **°**，1 LSB = 1/128 °                | 单位 **rad**，1 LSB = 1/128 rad                                                                                                                                    |
| `0x41` 控制模式线值                          | PP(0)、CSP(1)、CST(2)、HM(3)、CSV(4)、MIT(5) | 与 `datatypes.h` `control_mode_t` 一致（见下表）                                                                                                                        |
| 默认控制倾向                                 | 使能后常用 **CSV(4)**                        | 上电/默认常用 **速度开环 SPEED_OPEN_LOOP(10)**                                                                                                                            |
| 状态字节高 4 位（使能）                          | **等于 1** 表示使能                           | **非 0** 表示使能                                                                                                                                                    |
| 状态字节低 4 位                              | V1 模式枚举                                 | `control_mode_t` 低 4 位                                                                                                                                          |

| 周期上报 payload                           | 常见 **8 B** 有效区（pos/vel/Iq/status/error） | **18 B**（含 Id、三相电流、温压，见「周期上报」）                                                                                                                                  |

**V2.0.0** `0x41` **线值（**`control_mode_t`**）**

| 值 | 模式 |
| -- | ---- |
| 0 | IDLE |
| 1 | TORQUE（转矩环） |
| 2 | SPEED（速度环） |
| 3 | POSITION（位置环） |
| 4 | CSP |
| 5 | CSV |
| 6 | CST |
| 7 | MIT |
| 8 | HOMING（回零） |
| 9 | TORQUE_OPEN_LOOP |
| 10 | SPEED_OPEN_LOOP |
| 11 | POSITION_OPEN_LOOP |
| 12 | VOLTAGE |
| 13 | RESERVED |

> **注意：** 同一线值在两代含义不同，例如 V1 的 `0`=PP，V2 的 `0`=IDLE；V1 CSV=`4`，V2 CSV=`5`。对 V2 设备发 V1 模式字会导致停机或模式错误。

**V1.0.0 周期上报 error（保护类，bit7=0）子码摘要**

| 子码 | 含义 |
| ---- | ---- |
| 0 | 正常 |
| 1~2 | 硬件/软件过流 |
| 3~6 | 过压/欠压等 |
| 7~8 | 缺相/编码器 |
| 0x0E | 回零超时 |
| 0x0F | 丢帧 |

bit7=1 时为 IAP 子码表（与运动协议版本独立；IAP `0xFC` 另见本文 IAP 章节）。

**V2.0.0 周期上报 error（与 V1 相同线格式：BIT7=0 保护 / BIT7=1 IAP；保护子码由 **`can_fd_codec_fault_to_error`** 按 fault 主因映射）**

| 子码 (BIT6~0) | 含义 |
| ------------- | ---- |
| 0x00 | 正常 |
| 0x01~0x0F | 同 V1 保护子码表 |
| 0x10 | 电机轴硬超速 |
| 0x11~0x20 | 对齐/校准/饱和/看门狗/参数/短路/堵转/不平衡/采样/存储/制动/Desat/nFAULT/逻辑欠压/W 相开路/用户指令等 |
| 0x7F | 未分类保护故障 |

多 fault 位同时置位时仅上报 **优先级最高** 的一条（方案 A）。IAP 子码见 V1 bit7=1 表。

#### 0xAB 电角度对齐应答

请求为单播 Node-ID，DATA 1 B 为对齐方案（与 `cal_elec_align_method_t` 一致）。应答 CMD 仍为 `0xAB`，DATA **14 B**（CNT+CMD+14 = 16 B，DLC=16）。首字节保持 `error_t`，旧主机只读第 1 字节仍能判断成败。

| 偏移 | 长度 | 内容 |
| ---- | ---- | ---- |
| 0 | 1 | `error_t`：`0` 成功；对齐失败常见 `10`~`12`（见 `error_types.h`） |
| 1 | 1 | 方案：`0` Ud，`1` Uq，`2` Ud 双点，`3` Uq 双点，`4` HFI |
| 2 | 1 | 方向 `int8`：`1` = CW，`-1`（`0xFF`）= CCW，`0` = 未知 |
| 3 | 1 | 标志：bit0 对齐通过，bit1 本次翻转了方向，bit2 转子已吸合，bit3 电气对齐完成 |
| 4 | 4 | 对齐后电角 `int32` 大端，1 LSB = 1e-6 rad（`align_theta_after_rad`） |
| 8 | 4 | 电角零偏 `int32` 大端，1 LSB = 1e-6 rad（`theta_elec_offset_rad`） |
| 12 | 2 | 极性探针 Iq `int16` 大端，单位 mA |

失败时零偏可能已被对齐流程清掉，电角与探针仍按应答时刻的当前值回传。角度约到 ±π，微弧度用 `int32` 足够。

#### 0x53 电机本体参数应答

请求 DATA 长度 0。应答 CMD 仍为 `0x53`，DATA **16 B**（只读展示，无 SET 对应项）。

| 偏移 | 长度 | 内容 |
| ---- | ---- | ---- |
| 0 | 1 | 极对数 `pole_pairs` |
| 1 | 1 | 方向 `int8`：`1`=CW，`-1`（`0xFF`）=CCW |
| 2 | 2 | 减速比 `uint16` 大端，值 = ratio×1000（如 50 → 50000） |
| 4 | 4 | 电角零偏 `theta_elec_offset_rad`，`int32` 大端，1 LSB = 1e-6 rad |
| 8 | 4 | 机械零偏 `theta_offset_rad`，同上 |
| 12 | 2 | 编码器 `encoder_counts_per_rev`，`uint16` 大端 |
| 14 | 1 | 标志：bit0 = `electrical_align_done` |
| 15 | 1 | 保留 0 |

#### 0x00 周期上报

**CAN-FD 数据段布局（与** `can_fd_custom_send_frame` **一致）**

| 字节序 | 长度 | 内容 |
| ------ | ---- | ---- |
| 0 | 1 | **CNT**（帧计数，每发一帧递增） |
| 1 | 1 | **CMD** = `0x00` |
| 2~19 | 18 | **DATA**（下表；V2 本固件） |

V2 周期上报：**有效 DATA = 18 B**，加上 CNT、CMD 共 **20 B**，对应 CAN-FD **DLC = 20**（已为合法 DLC 档位，**不再**追加 `0x00` 填充）。解析周期数据时请跳过前两字节，或先剥 CNT/CMD 再按 18 B 解包。

V1 短格式：DATA 8 B → 线上总长 10 B → 按规则填充至 **DLC = 12**（尾部 `0x00`）。

**V2.0.0 DATA 区字段（偏移相对 DATA[0]，大端 int16 除非注明）**

| 偏移 | 长 | 字段 | 说明 |
| ---- | -- | ---- | ---- |
| 0 | 2 | pos | Q7，**rad**，raw/128；控制系关节角 |
| 2 | 2 | vel | 关节端转速 **RPM**（`int16` 大端），与 `0x02` 目标速度同单位；`rad/s = RPM_TO_RAD_PER_SEC(raw)` |
| 4 | 2 | Iq | mA |
| 6 | 2 | Id | mA |
| 8 | 2 | Ia | mA |
| 10 | 2 | Ib | mA |
| 12 | 2 | Ic | mA |
| 14 | 1 | status | 高 4 位：使能（非 0=使能）；低 4 位：`control_mode_t` |
| 15 | 1 | error | V2 故障压缩码（见「协议版本」） |
| 16 | 1 | MCU 温度 | 整数 ℃ |
| 17 | 1 | 母线电压 | 0.1 V/LSB（例：239 → 23.9 V） |

上位机若只拿到「去掉 CNT/CMD 后的 DATA」，V2 长度应为 **18**；若拿到整段 CAN 数据且 **DLC=20**，则 DATA 占后 18 字节。区分 V1/V2：**DLC=12** 且 DATA≤8 B 多为 V1 短格式；**DLC=20** 为 V2 本固件扩展上报。

**V1.0.0 短格式（兼容）8 字节有效区**

| 偏移 | 字段 |
| ---- | ---- |
| 0~1 | pos（Q7，**°**） |
| 2~3 | vel |
| 4~5 | Iq（mA） |
| 6 | status（V1 使能/模式规则） |
| 7 | error（V1 bit7 编码） |

部分旧文档描述 10 B 含温压的布局；以实机固件为准，对接本仓库 FOC 请按 **18 B** 解析。

# IAP

考虑到单总线多个电机升级情况，升级包数据段帧采样广播指令进行升级（当然，也兼容支持指定 node id 升级特定设备）。

## 数据帧格式

单电机升级IAP ID：Node-ID

统一升级IAP ID：0x7FF

| IAP ID | Data0 | Data1 | Data2-N |
| ------ | ----- | ----- | ------- |
| ID     | CNT   | CMD   | DATA    |

## 主机 -> 从机 IAP协议帧

典型时序：`0xF8 ENTER` → `0xF9 START`（擦除完成后应答 `0xFC`，state=2 / err=0x80）→ `0xFA DATA*` → `0xFB END` → `0xFE VERIFY`（查询 `0xFC`，成功为 state=5 / err=0x80）→ `0xFF RESET`。复位后由 Bootloader 把 staging 拷贝到 `0x08001000`。

App 将整包写入暂存区 `0x08010400`（最多 61×1KB），**含 32B ASIX 头 + 固件体**。`0xF9` 首帧 Data2 起即为该头，后续 DATA 续写，不剥离头。

| 偏移 | 长度 | 字段 | 说明 |
| ---- | ---- | ---- | ---- |
| 0 | 4 | Signature | `'A''S''I''X'` |
| 4 | 2 | ImageType | 小端，必须为 `3` |
| 6 | 2 | Compress | 0 |
| 8 | 4 | ContentOffset | 0 |
| 12 | 4 | FileLen | **大端**，整包长度（头+体） |
| 16 | 4 | Reserved0 | 0 |
| 20 | 4 | Checksum32 | **小端**，对体做 32 位 ones-complement 累加后取反 |
| 24 | 8 | Reserved1 | 0 |

| **CMD功能码**       | **Data LEN** | **说明**          | **备注**                                                  |
| ---------------- | ------------ | --------------- | ------------------------------------------------------- |
| 0xF8（不应答）        | 0            | 从 MCU 进入 IAP 模式 | 失能电机、停止周期上报；IAP 期间丢弃控制帧 |
| 0xF9（应答cmd=0xFC） | ≥32          | 开始升级            | Data2 起 32B ASIX 头 + 首段固件；擦除 staging 后应答 `0xFC`，再写入本帧 |
| 0xFA（不应答）        | x            | 升级数据            | 按 CNT 连续；填充字节使用 `0xFF`；超过 FileLen 的填充不写入 Flash |
| 0xFB（不应答）        | 0            | 结束升级            | 刷新不足 4 字节的尾部缓存 |
| 0xFC             | 0            | 查询升级状态          | 出错时从机也会主动上报 `0xFC` 并回到空闲 |
| 0xFD             | 0            | 查询固件版本          | |
| 0xFE（不应答）        | 0            | 验证固件            | 校验 `Checksum32` 与 Flash 体；成功后查询 `0xFC` |
| 0xFF（不应答）        | 0            | 复位              | `NVIC_SystemReset()`，Bootloader 接管 |

帧超时 3s（从最近一帧 IAP 命令起算；START 内同步擦除期间主循环阻塞，不计入超时）。

## 从机->主机IAP应答

| **CMD功能码** | **有效数据域长度** | **说明**      | **备注** |
| ---------- | ----------- | ----------- | -------- |
| 0xFC       | 2           | 返回IAP状态、错误码 | Data2=state，Data3=error |
| 0xFD       | 13          | 返回固件版本      | `V` `.` `_` 为 ASCII，主/次/修订与日期为原始值。例：`00 FD 56 03 2E 01 2E 05 5F 1A 06 0A 0B 1E 0F` → `V3.1.5_260610113015` |

### IAP 状态（0xFC Data2）

| 值 | 状态 |
| -- | ---- |
| 0 | 空闲 IDLE |
| 1 | 准备 READY（已 ENTER） |
| 2 | 接收 RECEIVING（START 擦除成功） |
| 3 | 验证 VERIFYING（已 END） |
| 4 | 编程 PROGRAMMING（保留，App 侧未用） |
| 5 | 完成 COMPLETE（VERIFY 已执行） |
| 6 | 错误 ERROR（随即回到 IDLE） |

### IAP 错误码（0xFC Data3）

| 值 | 含义 |
| -- | ---- |
| 0x80 | 成功 |
| 0x81 | 无效命令 |
| 0x82 | 无效参数（签名/类型/长度） |
| 0x83 | Flash 擦除错误 |
| 0x84 | Flash 写入错误 |
| 0x85 | Flash 验证错误 |
| 0x86 | CRC 校验错误 |
| 0x87 | 超时 |
| 0x88 | 设备忙 |
| 0x8C | 拒绝（状态不允许） |
| 0x8F | 丢帧（CNT 不连续或长度不足） |

## 单播处理确认与指令延迟诊断（本次扩展）

- 普通命令（非 IAP，且非应答专用0x7E）以本机 Node-ID 单播时，命令分发返回后追加 `0x7E` 应答。DATA为2字节：原请求CNT、原请求CMD；应答帧自身CNT仍是从机发送计数。
- `0x7E`只确认该请求已走完分发，不表示动作成功或电流已收敛。未知命令、参数/状态不允许的操作也不能凭此判断成功；操作结果仍读取原有专用应答。IAP保持其原握手协议。IAP会话中被忽略的普通命令不发此确认。
- `0x40 ENABLE`新增同CMD、1字节error_t结果：0成功；错误码由mc_enable/mc_disable返回。只接受DATA首字节0/1；空数据或其他值返回ERR_PARAM。成功表示API接受/执行状态切换，PWM生效仍受下一次控制中断和保护状态影响。
- `0x41 CONTROL_MODE`保持同CMD、1字节error_t结果。运行中切换非IDLE模式会返回ERR_STATE，不能理解为排队等待切换。
- 普通广播命令执行但不通过普通应答函数回包，避免多机同时应答；单播专用功能和IAP例外规则维持原定义。前文0x40/0x41“不应答”描述仅适用于广播。
- 普通应答进入16槽队列，在发送邮箱忙时由主循环重试，优先于周期遥测。队列溢出计数为固件静态变量s_reply_drops，可在调试器检查；容量不是无限的，请勿无界下发。
- 长时间校准/验证仍在前台同步执行，处理确认在结束后返回；不得把该确认当成即时中断级接收确认。修改Node-ID/恢复出厂后应答可能使用新Node-ID，主机旧ID的RTT匹配不保证成功。
