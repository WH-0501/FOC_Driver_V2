# 正常遥测与三环 PID 调试共用示波工作台

## 使用与布局

1. 连接 V2 固件，打开“实时示波器”。顶部选择“正常遥测”或“PID 调试”。这只是显示/订阅选择，不切换电机控制模式、不修改 PID，也不自动使能。
2. PID 调试选择电流环、速度环或位置环。选择“订阅当前环”或“订阅三环”，设置 Hz/环，点击“开始 / 应用”。默认 100 Hz/环，单环最高 1000 Hz，三环最高 333 Hz/环，总帧率不超过 1000 Hz。
3. 默认显示环内给定与反馈，使用相同量程。误差、Iq/Id、积分、输出可直接勾选；其他参数在“更多调试信号”中展开。右侧常驻正常状态，下方保留运动控制，不再显示 PID 快照卡。波形本体与正常工况共用，不复制旧版弹窗。
4. “阶跃 / 数据分析”打开共用分析页面，数据源、通道名称与单位跟随当前所选环。复用 T1/T2、统计、FFT、阶跃列表和逐条详情。“返回共享示波器”回到原波形页面。调参页保留写入/回读功能，用入口按钮跳转到同一调试示波器，不再有第二套订阅控制。

普通工况使用原正常遥测和主机已提交目标；调试工况使用 B9/BA/BB 回传的环内 reference/feedback。速度环为 rad/s，正常速度遥测仍为 RPM。电流环给定/反馈 A、输出 V；位置环给定/反馈 rad、输出 rad/s。XY Id/Iq 模式仅在正常遥测下可用，避免错误解释调试通道索引。

## 时间与分析可信度

调试 X 轴采用各环 PID 更新时间戳，单位 us，转换为相对该环首个有效时间戳的秒数。兼容真正的 32 位微秒回绕，以及当前 180 MHz 固件的 DWT 换算微秒回绕（周期约 23.860929 秒）。按回绕前后端点与接收时间间隔校验；重复时间戳与小范围迟到帧不重复插入历史。无法确认为回绕的回退保留历史并另开运行段，以主机间隔衔接显示轴，跨段禁止阶跃测量，原始设备 tick 保留在 CSV。环停止/恢复产生新的运行段；未执行环不生成有效阶跃指标。

这比主机点击/排队时间更贴近设备控制状态，但固件通过主循环抽样发送调试快照，并未上传所有控制周期。首次观察到新给定的帧不一定等于实际指令生效的控制周期。阶跃详情因此保留前一帧到新给定帧的时间区间及采样间隔，不承诺超过采样频率的精度。PID dt 是控制器更新时间间隔，不等同于调试上报间隔。Iq/Id、母线与轴速度为发送快照，而 reference/feedback、积分、输出属于 PID 状态。

PID 自动阶跃分析要求变化前后给定各保持至少 5 个不同 PID 时间戳的样本，避免把闭环中每帧变化或反复触碰限幅的内部给定当作大量阶跃；短脉冲/持续变化可用手动目标和 T1/T2 区间分析。正常工况的全部目标变化列表规则不变。每条阶跃在下一次给定变化前结束；参数、单位、时间来源写入详情及导出。

## 数据与生命周期

- 正常历史与三环历史独立。三环可同时采集，在同一个大波形窗口中切换查看，避免不同环、不同单位和时间来源混画。
- B8 单次开启后持续回传，不再续租、没有3秒到期。停止、切回正常、切换节点或正常断连时发送关闭；固件复位或升级也会退出调试。异常断开时设备保持已选上报模式，重新连接后可用停止按钮显式退出。
- 每环独立保留 12 万个唯一 PID 时间戳样本；默认 100 Hz 时约 20 分钟。满后覆盖旧数据。正常记录容量设置保持独立。
- 清除只清除当前显示源/当前环的内存记录、抓拍和分析结果，不影响正常遥测或其他环；仍复用原清除/导出取消逻辑。
- 调试 CSV 导出当前环所有记录，包含相对设备时间、节点、环号（1/2/3）、运行段以及 **24** 个数值列（与 `debugChannelNames` 一致）：反馈、误差、Iq、Id、PID dt、积分、输出、母线、轴速度、Kp、Ki 配置、给定、输出限幅、积分限幅、斜坡、P 项、有效 Ki、活动标志、原始 tick、flags，以及 **FOC 四路环耗时 µs**（payload v2；v1 帧后四列为空）。三环分别切换并导出。正常 CSV 保留原列顺序。
- 原始调试帧：**v1** 要求 14 个浮点均为有限值；**v2** 要求 12 个浮点 + 4×u16 环耗时。错误长度/版本/NaN/Inf 整帧拒绝；调试无效帧告警限频，避免异常流造成界面日志洪泛。

## 工程验证与资源

沿用分块峰值索引、像素包络、后台分析和原始缓存。统一通道槽扩展为 **24** 个（含 FOC 环耗时），正常百万点内存估算约 197 MB（界面显示值，不含所有容器/索引开销），这是完整调试字段带来的内存成本。

本机 1200×650 离屏测试：正常 12 通道全部显示、百万点历史、5 秒视窗平均 4.84 ms/帧；PID 20 通道全部显示、12 万点历史、5 秒视窗平均 6.59 ms/帧，120 秒全历史平均 12.35 ms/帧。不是实际 CAN 持续采集吞吐保证。

回归覆盖：B9/BA/BB 字段解码与单位、NaN 拒绝、时间回绕/重复/回退、设备来源阶跃、连续给定过滤、CSV 全字段及取消、三环 Demo 续租超过 3 秒、普通记录隔离、显示源/环切换、共用阶跃列表、停止调试流和原有功能。完整 CTest 8/8 通过。真机尚未验证，本次没有发送真机控制指令，也没有修改旧 Python 代码或烧录固件。

## 暂停缩放修复

暂停显示时冻结当前数据源的完整历史及峰值索引。X/Y 缩放、平移、游标、查看全部记录、阶跃分析和 CSV 导出都使用冻结记录，后台继续采集，即使实时环形缓存完全覆盖也不影响暂停视图。恢复显示释放冻结记录；切换数据源会冻结新数据源，清除会同时清除当前冻结记录。暂停期间额外占用一份当前历史内存。

回归复现覆盖：200 点 PID 历史暂停，后台追加 400 点完全覆盖原缓存，再滚轮缩放与查看全记录，图像和阶跃结果保持一致；恢复后读取新数据。另覆盖连续给定触碰限幅不产生伪阶跃，以及正负真实阶跃仍可检测。

T1 / T2 开启时按当前可见时间范围的 25% / 75% 放置游标，不再使用固定秒数偏移，因此窄时间窗口中也能直接看到两条线。再次点击关闭，再开启会重新定位到当前窗口。

## DWT 回绕兼容修复

固件 `dwt_get_ticks_us()` 将 32 位 CYCCNT 乘以 1/180 转为微秒，所以其回绕周期不是 2^32 微秒。本次仅修复上位机，不修改/烧录固件。正常回绕不清空历史、不弹警告；无法确认的时间不连续记录 INFO 并分段。小范围乱序（100 ms 内）和回绕后的迟到旧帧丢弃，不推进时钟锚点。

回归包括按固件 float 换算生成的 100 秒、100000 帧连续数据（多次 DWT 回绕）、真正的 uint32 微秒回绕、重复时间戳、迟到帧、真正回退及长中断。不同 CPU 频率或未知计时方案不猜测周期，走保留历史分段路径；跨段的显示时间含主机衔接，不用来计算设备响应时间。

## 上层目标回传（需配套固件）

新版固件 B9/BA/BB 的 reference 分别回传设备保存的 ref.iq / ref.speed_rad_s / ref.position_rad，始终取上层目标，不取软限速修正或外环 PID 输出。其余反馈、积分、PID 输出、时间戳仍为实际控制状态；软限速及保护功能保持不变。

帧长、schema、字段顺序与单位不变，flags bit3=1 表示 reference 为设备上层目标；旧固件 bit3=0 仍解释为环内实际给定。上位机不能将旧固件回传的限速后值还原为原目标，必须更新设备固件才生效。新帧的目标误差表示上层目标减反馈，不再据此伪造实际 PID P 项（P 项显示缺失，CSV 空列）。串级模式下电流目标/速度目标可能不是实际内环输入，不能当作独立环的固定输入实验。

目标值在 CAN 中断更新，而 PID 更新时间属于最近控制周期，调试仍是抽样快照，阶跃时刻仍只具有采样区间精度。

验证：编译实际 can_fd_debug_send 函数，设置原始电流 .25A、PID 目标 .12A，确认回传 .25A；同时验证速度 2rad/s、位置 -1rad 的字段字节、bit3 标记、流量限制及租约。58 个 ARM 目标文件完整编译链接，生成 HEX/BIN；未烧录、未真机运行。

## 单次切换上报模式

上位机移除续租定时器；启用或应用配置发送一次 B8，设备持续回传所选 B9/BA/BB。暂停显示不发送 B8。停止或返回正常发送 B8 mask=0，恢复原普通遥测频率。

调试开启时普通遥测降为 5 Hz，仅供状态、故障、使能/失能确认和失联监测，避免两路同时高速上报；PID 调试仍按配置频率运行。这不会轮询 B5。需要配套新固件，否则旧固件仍会在3秒后停止。

新增验证：不续租超过3秒仍持续采集，期间日志无 B8 TX；固件协议测试跨3秒保持订阅、升级停止。已编译固件但未烧录。

## 调试状态帧超时修复

此前用16位 TMR6 原始值直接判断200ms周期，导致状态帧可能长期不发。已改为逐次累加 uint16 模差，在65.536ms硬件回绕后仍保持200ms状态上报，繁忙时累加但不补发突发数据。正常模式1Hz等低频上报同步修复。SYNC重置计时基准与累计值。

真实调度函数的离线复现：旧实现在10秒内0帧；修复后50帧。覆盖1Hz/1000Hz正常遥测、应答队列繁忙与恢复。上位机超时急停逻辑未修改。固件58目标文件重新编译链接，保留原有编译警告；尚未烧录真机。

## 操作日志

新增 ACTION 记录，包含操作名称、请求编号、节点、CMD、参数字节及待发送状态。运动控制按钮记录实际编辑值与单位；电流归零和普通电流下发区分记录；限速记录软限速RPM和硬保护配置，首次自动读取与手动读取区分。启停、模式、复位、扫描、调试配置有命令名称，其余协议请求保留CMD及原始参数。

实际发送后的 INFO 记录将请求编号关联到CNT，目标电流等不等待专用应答的命令也记录主机排队时间。ACTION表示提交请求，不代表设备执行成功；TX驱动提交耗时也不是电流建立时间，ACK只代表设备分发确认。现有原始TX/RX、错误和遥测确认保留，不增加成功弹窗。

## 通信延迟分段计时与事件唤醒

ACTION 时间取命令入口现场；TX/RX/INFO/TIMING 时间在 Session 发出日志现场记录，界面只显示该时间，并对ACTION/TX/TIMING附加 UI投递毫秒数。界面绘制不再改变这些时间戳。请求先入队，界面日志使用排队连接；不再同步写日志后才入队。

Session 使用条件变量：新命令与原生接收帧都会唤醒工作线程，取代固定每轮sleep(1)。原生接收队列每次交付至多256帧，给待发命令留出处理机会。原生接收空闲轮询采用Windows高精度可等待定时器（0.5ms目标等待；不承诺调度上限），旧Windows或API失败回退原1ms等待。不修改DLL ABI、发送模式、帧格式或自动重发规则。

TIMING 字段：入口→入队包括格式化、队列锁等待等；入队→发送包括队列和线程调度；TX调用及记录包括驱动调用与发送状态记录；原TX行驱动提交字段保留。ACK按节点、CNT和CMD关联，记录TX开始→主机取ACK、驱动取帧调用（含GetReceiveNum）、RX队列→解析、入口→解析。匹配记录最多256条、30秒；身份复用歧义不计算延迟。

ControlCANFD/ZCAN原生FD与经典CAN接收结构的64位timestamp（微秒）完整保留，并打印适配器RX原始值；零也合法。它是适配器时钟域，绝不与主机steady_clock相减。当前ZCAN_TransmitFD只返回提交帧数，其发送结构没有TX时间戳，因此无法仅凭此API将USB、总线、MCU时间分别量化，也不将收到的ACK当成TX回显。桥接后端没有这套原生元数据时明确显示不可用。

解读：若入口→入队大，查界面提交及锁等待；入队→发送大，查工作线程负载；RX队列→解析大，查批量解码；UI投递大但前几项小，属于界面日志延迟；TX→主机取ACK仍大、取帧调用和解析小，则剩余在驱动/USB/适配器/总线/设备路径，需TX硬件时间戳或外部CAN分析定位，不能称作纯总线延迟。

验证包括原生假DLL的ABI和独立收发、64位时间戳保留、接收唤醒；故意阻塞UI线程80ms，工作线程仍完成发送/ACK解析并形成源头TIMING记录。此测试不是实际200U硬件时延保证，仍需使用新版真机日志复核。
