# 主机目标事件与设备时间分析

## 时间基准

正常遥测页面：目标线来自独立主机目标事件，横坐标是主机单调时钟；反馈点使用主机从驱动取帧的时间（桥接后端缺少该时刻时使用解析时间）。测量包含排队、通信、设备和回传延迟，属于端到端响应，不能当作纯PID动态指标。

PID调试页面：仍使用设备回传目标和PID时间。切换正常/PID页面即选择对应的分析基准，不将设备时钟直接与主机时钟相减。

## 事件生命周期与绘图

每条事件独立保存请求编号、节点、编码后的目标值、入队时间、驱动提交时间、ACK时间及状态。状态为 queued / submitted / acknowledged / rejected_or_cancelled；-1时间表示尚无对应阶段。ACK仅表示分发确认，不代表电流已到目标。

队列入队时记录事件，拒绝或取消同样留痕；只有已提交驱动/已收到ACK的事件进入目标曲线与自动阶跃列表，避免把未发出的请求当成设备动作。曲线拐点使用原始入队时刻，按水平段与垂直跳变绘制。后台事件记录不主动同步重绘UI，显示仍按既有刷新节奏。

每个当前会话最多保留10000条事件，避免无限增长；切换节点、重新连接或清除记录同步清除对应事件。暂停冻结历史时同时冻结事件；触发/故障捕获取对应捕获时的事件快照。

## 阶跃与导出

正常工况自动阶跃从已发送事件分段，不再把相邻遥测点的目标变化时刻当作精确入队时刻。详情包括 step_time_s（入队时间）、driver_submitted_s、ack_s、request_token、first_feedback_after_event_s、enqueue_to_90_ms。10%→90%指标仍是反馈交越之间的时间，不能与入队→90%混淆。采样不足时保留事件并报告无法测量，不补造反馈样本。

正常CSV保持现有列顺序，time改为主机反馈接收时间；旁边生成同名 `.targets.json`，保存完整事件状态及精确时间。暂停后导出可确保使用冻结记录。活动采集时导出以快照/导出范围为准，不保证后续新事件包含在已启动的导出中。

## 适配器时钟与FFT

原生适配器原始64位RX时间戳保留诊断。大于int64最大值的值（如用户提供的18446743947967255416）标记异常，仅保存原值，不猜测有符号转换，不参与波形时间对齐。有效范围不等于已证明绝对时钟校准。

FFT单独保留有效适配器相对采样时间，在其间隔满足原有一致性检查时计算频率，避免主机USB批量取帧导致相同接收时刻破坏频谱；PID FFT继续用设备时间。没有可靠间隔则沿用拒绝不均匀采样的行为。

## 验证

覆盖精确入队时刻（事件0.505秒、首个反馈0.510秒）、失败事件排除、ACK状态、冻结/清除、JSON事件导出、异常uint64时间戳隔离、主机批量收帧情况下125Hz频谱保持正确，以及既有CAN兼容、运动控制和示波回归。未向真机下发指令，无固件修改。
