# 电机调试工作台改造说明

本轮采用现有 Python + PyQt5 + NumPy + pyqtgraph，优先消除数据结构和事件队列瓶颈。
这是可运行的功能扩展版本，尚未完整复现 VOFA+，也没有做实物 CAN 盒与电机验证。

## 已实现

- 顶部连接区、中央示波器、右侧可滚动电机控制、底部日志；连接与日志可停靠、浮动和隐藏，通过“视图”菜单恢复。
- 时域、FFT、XY、64 格直方图、最新值条形图。时域各通道沿用协议单位，混合单位共用一个 Y 轴。
- 冻结显示与采集分离。滚轮缩放保持实时刷新，保留缩放后的时间跨度与手动 Y 量程；拖动图形自动冻结并关闭 Y 自动量程，保留独立完整快照；缩放时重新截取原始数据，避免历史放大后只剩抽样点。
- 时域双游标：Δt、1/|Δt|、选定通道 Δy。Δy 使用游标右侧最近采样点；超出缓存范围显示 `--`。
- 原始可视数据的 min/max/mean/RMS；旧固件未上报的 Id/Ia/Ib/Ic 使用 NaN，避免假显示为零。
- 可选每电机 1 万 / 12 万 / 100 万点环形缓存，预分配 NumPy 数组；扩容/缩容保留最新数据。默认 12 万点，1 kHz 约 120 秒，保留时长取决于实际采样率。
- 最多 32 台电机、环形数组总计最多 384 MiB，超限淘汰最近最少使用的非当前电机。冻结快照、导出快照和临时分析数组额外占用内存。
- 显示端按像素预算取桶内极小/极大值，保留尖峰，通常每通道最多 4000 点；原始缓存及 CSV 不降采样。并非百万点无降采样 GPU 绘制。
- 绘图目标间隔 33 ms；未变化/冻结时不重复计算。显示的耗时只包含数据准备与 setData，不包含 Qt 实际绘制。
- 周期遥测改为 32768 帧有界队列，16 ms 周期每次最多消费 1024 帧；队列过载丢弃最旧遥测，状态栏显示计数。IAP/控制应答保留独立 Qt 信号通道。
- CSV 导出所有原始缓存；冻结时导出冻结快照。先复制快照，然后后台写文件，写入期间仍可接收。导出中的文件可能尚未写完，等待完成通知。
- 日志限制 2000 段；切换电机时目标曲线正确绑定当前 Node-ID；扫描发现首个电机后结束自动切换，避免周期上报反复切换当前电机。

## 分析与操作

1. 启动 `python motor_gui.py`，选择原来的 CAN-FD 设备并连接；原协议版本、DLC 填充、PID 编解码及 IAP 帧格式保持原实现。
2. 在示波器选择缓存容量和显示窗口。滚轮缩放后继续实时跟随，横轴保持缩放后的窗口宽度；拖动进入历史查看；“实时跟随”回到最新数据；“重置视图”恢复 6 秒与 Y 自动。
3. 勾选“双游标”，拖动两条竖线；“Y / 测量”指定 Δy 与统计通道。FFT、XY、直方图也使用该 Y 通道。
4. FFT 使用最后 N 个原始样本、Hann 窗、去直流、单边幅值标定，点数可选。实时模式分析当前时间窗口，冻结模式分析冻结缓存末尾 N 点。
5. FFT 横轴依赖设置的设备采样间隔，默认 1 ms。CAN 到达时间不能保证等间隔；丢帧、固件采样抖动会使频谱失真。这里未做重采样或丢帧修复。
6. XY 可选择独立 X 通道，按时间顺序等步抽样限制绘制点数。直方图分析原始数据；条形图按曲线选择器顺序显示勾选通道的最新值。

时间轴保留正向硬件时间戳间隔（含通信停顿），重复/倒退/无效时间戳以 1 ms 展开。
这不是设备采样计数器，批量硬件时间戳精度不足时仍有误差。缓存保留容量按点数限制。

## CAN / CAN-FD 边界

| 后端 | 本轮支持 | 边界 |
|---|---|---|
| 原 ZQWL / 创芯厂商 DLL | 保持 CAN-FD 接收与发送逻辑 | Windows 专用，需原驱动和 library 文件 |
| 原 PCAN-USB 预设 | 保留 FD 模式 | FD 需要支持 FD 的硬件和正确的厂商位时序配置；未做硬件验证 |
| PCAN-USB（经典 CAN） | 新经典 CAN 预设 | 1 Mbps，标准帧，最大 8B |
| SLCAN | 修正为经典 CAN | 需串口；不再错误标记为 FD |
| SocketCAN | 新 CAN / FD 预设，默认 can0，可编辑通道名 | Linux 下先通过系统工具配置接口、仲裁/数据波特率并启动 |
| Virtual CAN-FD | 新软件总线 | 供模拟与回归，不连接物理电机 |

经典 CAN 复用已有短命令格式 `[CNT, CMD, DATA...]`。超过 8B 的控制/批量/升级命令明确拒绝，不截断、不自动分包。
原旧周期上报有效 8B，加帧头共 10B；新版为 18B。因此**原完整周期遥测与 IAP 无法直接运行在经典 CAN**。
若要通过经典 CAN 完整调试，必须与固件共同定义新的分包/重组或精简遥测协议。本轮没有新增该固件协议。

应用层使用 Qt 与 python-can，移除了非 Windows 平台导入 `ctypes.windll` 的阻断。
Windows 已运行 GUI；Linux/macOS 尚未实机验证。macOS 需另选具有可用驱动的 python-can 后端，不能使用 Windows DLL 或 SocketCAN。

## 可重复验证

环境：当前 Windows 主机、Anaconda Python，2026-10-28。结果不是实物总线性能承诺。

```shell
python -m unittest discover -s tests -v
python tools/benchmark_waveform.py
python tools/benchmark_gui.py
```

- 10 项测试：环形回绕、窗口截取、快照独立、扩缩容、缺失电流、时间戳、峰值预算、FFT 频率/幅值、FD 发帧一致性、经典 CAN 拒绝长帧、虚拟总线、遥测过载/应答分离、冻结与五种显示模式（若干测试覆盖多个断言）。
- 缓存写入约 358719 样本/秒；12 万点 × 10 通道快照及峰值包络 P50 9.48 ms / P95 10.60 ms；单台默认环形数组 10560000 字节。
- GUI 虚拟总线：21 电机 × 1 kHz × 5 秒，105000 帧发送、105000 样本缓存、0 队列丢帧、排空后积压 0；16 ms 心跳间隔 P95 20.13 ms / 最大 54.72 ms，显示当前电机 10 条曲线。
- 上述心跳指标衡量事件循环响应，不等于绘制帧率；百万点缓存需另按目标机器验收。工具不会向真实 CAN 通道发帧。

## 与 VOFA+ 的差距及后续阶段

参考：[VOFA+ 官方波形文档](https://www.vofa.plus/docs/learning/widgets/wave/)、[pyqtgraph PlotDataItem](https://pyqtgraph.readthedocs.io/en/pyqtgraph-0.13.7/api_reference/graphicsItems/plotdataitem.html)。

1. 电机优先功能：位置/速度/电流独立量程与同步多窗、通道增益/偏移、触发源/边沿/阈值/前后触发比例、过流事件抓取、长时间磁盘记录与回放。
2. VOFA+ 进一步对齐：分析图与时域同时显示、多游标、任意点与游标测量、三点占空比、可配置直方图范围和桶数、布局保存。当前双游标为独立实现，操作和数值规则未完全复制 VOFA+。
3. JustFloat：单独新增字节流解码器（小端 float32 + `00 00 80 7F` 尾标）、分包/粘包/重同步与通道数配置；对接串口/TCP/UDP，再映射统一样本结构。其数据不天然带 Node-ID、位置单位或采样时间，需要连接配置；不用于替代 CAN-FD 命令协议。本轮仅规划，未接入 UI 或宣称可用。
4. 性能升级门槛：在目标机器上测实际帧率、接收丢帧、队列延迟、内存与磁盘吞吐。若百万点全量绘制、更多电机或长期记录使现架构超标，再迁移 C++/Qt 接收与缓冲、GPU 绘图；保留协议回归向量。当前模拟吞吐表明无须先整套重写才能获得明显改善。

### 建议下一阶段验收

- 目标 Windows/Linux 机器与真实 CAN-FD 盒连续 30 分钟，多电机各 1 kHz，核对固件帧计数与接收计数，并记录真实 paint 帧率/P95 延迟；不得只以定时器频率代替刷新率。
- 一百万点每通道的缩放、冻结、恢复、CSV 导出与内存回收；验证 CAN-FD 所有命令/PID/IAP 与固件行为。
- JustFloat 拆包、粘包、噪声、尾标出现在数据中的歧义及断线恢复测试后，才开放对应连接选项。

## 缩放刷新修复（2026-10-28）

原先 ViewBox 的手动量程信号将滚轮缩放也识别为冻结，导致后续只显示冻结快照。现将平移手势与缩放分离：滚轮保持实时刷新，拖动或“冻结显示”才冻结；已冻结时滚轮继续查看该快照。新增实际 Qt 滚轮事件与拖动信号回归，12 项测试通过。
