扫频频率与计时说明
依据当前 develop-V3.0 源码，2026-11-26

适用范围
以下数值按当前设备采样率 20,000 Hz 计算，每采样周期 50 μs。
设备仅生成激励、同步采样和上传；原始 H1/相干性由上位机计算。
请求频率通过现有 CAN-FD 帧以整 Hz 发送；结束频率必须大于起始频率。
请求范围为 20–2000 Hz，结束还必须不超过采样率的 1/10。
设备配置允许采样率 10–40 kHz，但本板当前为 20 kHz，不是修改频点数就会变。
两模式频点数均为 3–16；起始 >40 Hz 时至少 4 点，20/40 Hz 基准占其中 2 点。
参数的电流范围校验不等同于任意工况都安全，运动/时序/限幅保护保持不变。

一 周期线性 Chirp
实际激励起点 = 请求起点（<=40 Hz 时），否则实际从 20 Hz 扫到请求终点。
因此起始设置 600 Hz、结束 1600 Hz 时，设备仍然实际扫 20–1600 Hz；
上位机只在 20、40 Hz 及选定的 600–1600 Hz 谱线显示 H1。

一个周期包含 fs 个采样，持续 1 s；相同波形重复 4 次，总采集 4 s。
首个 1 s 周期为稳定段，后 3 个完整 1 s 周期分别估计并平均。
每周期头尾有约 5 ms 平滑包络，并做去直流/峰值归一化；端点附近能量会受影响。
频率由 DDS 相位步长逐采样递增，不是在 16 个频率上各停留 250 ms。
忽略 DDS 整数量化，f[n] = f_low + (f_high - f_low) * n / (fs - 1)。
20–2000 Hz 时，每采样增加约 0.09900495 Hz。
整个 1 s 周期的平均扫速约 1980 Hz/s；跨过 1 Hz 约需 0.505 ms。
有限频带宽度 B 的停留时间约为 B / 1980 秒，例如 20 Hz 宽约 10.1 ms。
这不是某条 H1 谱线只用 0.505 ms 来计算：每条选定谱线使用完整 1 s 窗口，重复 3 次。
同理，每个“频点”没有单独稳定段，也不存在统一的 4 s / 点数 检测时间。

Chirp 的对数点数
上位机按对数频率选出 N 条谱线，四舍五入到整 Hz，保证递增。
1 s 计算窗口对应 1 Hz DFT 间隔；点数主要决定计算/显示/导出哪些谱线。
改变 N 不改变实际扫频起终点、每采样频率增量、1 s 周期或 4 s 录波长度。
但 N 并非完全不下发：设备接收、校验并保存 count，进度显示也使用 count；
它不参与 Chirp 的相位步长和周期长度计算。

二 逐点正弦
请求起点 >40 Hz 时，设备先在 20、40 Hz 分别测试，然后跳到主频段；
不会像 Chirp 一样把基准和主频段之间所有频率连续扫过。
主频段名义频点按对数间隔生成，相邻频率比约为 (f_high/f_low)^(1/(M-1))。
M 是扣除基准后的主频点数；不是固定 Hz 间隔，也不沿用旧快速多正弦的 20 Hz 网格。
每点每周期采样数 P 是整数，实际频率 = fs / P。
上位机计算 period[]，使用现有 AD/1 扩展计划下发；固件校验并逐项执行。
中间点还要满足周期数严格递减并给剩余点预留不同周期，因此点数变化可能改变旧频点的位置。
实际频率可能略超出请求端点：如 600 Hz -> 606.0606 Hz，1600 Hz -> 1538.4615 Hz。
请求 850–1100 Hz 时，可用 P=24…18，仅 7 个主频点；加 2 个基准最多 9 点。
所以 16 点不合法，8 点可行。更多点不突破整数周期的频率量化限制。

逐频每点检测时间
P = 该点的整数周期采样数
稳定周期数 S = max(4, ceil(ceil(fs/50) / P))
稳定时间 = S * P / fs
测量时间 = 4 段 * 4 周期 * P / fs = 16 * P / fs
该点总激励和录波时间 = (S + 16) * P / fs
稳定段不进入 H1，但仍被同步录波上传。切换点后从该点的稳定段重新开始。
例如 20 Hz：稳定 200 ms + 测量 800 ms = 1000 ms。
40 Hz：稳定 100 ms + 测量 400 ms = 500 ms。
800 Hz：稳定 20 ms + 测量 20 ms = 40 ms。
1250 Hz：稳定 20 ms + 测量 12.8 ms = 32.8 ms。
总时间为所有点的时间之和；不包括启动准备、CAN 尾部传输和上位机分析显示开销。

逐频的对数点数
会影响实际下发的频点/周期列表、频率间隔和总测试时间，不只是主机显示密度。
不会改变固定的 fs、每点至少 20 ms/4 周期稳定规则、4段×4周期估计规则。
点数上限同时存在于固件结构、校验、协议计划及主机元数据中，不能只扩大 UI 数字框。

三 fc 本次修复
fc 仍是原始闭环 H1 的 >=100 Hz 绝对 0 dB 向下交点，仅用于诊断。
相邻有效点按对数频率插值，不要求端点恰好为 0 dB。
门槛作用于算出的交点频率，允许 93–126 Hz 内出现 >=100 Hz 的交点。
处理正值到零、零到负值；整段全零不制造交点。只上穿不算本定义的 fc。
无效点/非有限增益只断开所在区间，不跨点连接；继续搜索后面的相邻有效线段。
若之前有缺口，后面的交点显示“fc 候选（首次未确认）”，不宣称是首次交点。
<=40 Hz 基准直接跳到 >100 Hz 的空档不做 fc 插值。
原始 H1 和 -3 dB 带宽判定完全不变；带宽仍会因首次交点前的无效点拒绝确认。
主窗口和 Chirp 离线分析共用同一套 fc 逻辑；滤波/邻频结果不替代原始 H1。

源码位置
motor_controller/project/APP/FOC/sweep/sweep_engine.c：参数校验、逐频周期计数、Chirp 四次重复。
motor_controller/project/APP/FOC/sweep/sweep_chirp.c：DDS 频率步长、包络及归一化。
motor_controller/project/APP/FOC/sweep/sweep_protocol.c：读取起止频率、count 及 AD/1 计划。
motor_controller_hmi/src/sweep_recording.cpp：逐频对数网格、整数周期量化、主机分段 H1。
motor_controller_hmi/src/chirp_analysis.cpp：Chirp 整 Hz 选线、首周期舍弃及三个周期 H1。
motor_controller_hmi/src/sweep.cpp：fc 诊断交点及未改变的带宽判定。
