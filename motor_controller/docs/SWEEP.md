# 模块化扫频与电流闭环频响分析

## 本次实现与使用入口

基于当前主工程 `f3cf48c` 实现设备端扫频。主工程原有 MotorTune 的设备扫频界面、协议解码、Bode 图和 CSV 导出已存在，但当前固件没有对应执行模块。本次补齐固件，保持原 `0xBC/0xBD/0xBE` v1 协议兼容。

当前默认编译关闭扫频（`FOC_SWEEP_ENABLED=0`）；需要设备测量时全局定义 `FOC_SWEEP_ENABLED=1` 构建诊断固件，再通过协议启动。RAM 优化、隔离机制及计时实测方法见 [SWEEP_OPTIMIZATION.md](SWEEP_OPTIMIZATION.md)。

在 MotorTune 的「数据分析 → 扫频 / 带宽测试」选择「设备逐频正弦」或「设备快速多正弦」。先在正常调试流程中完成校准，选择 CST、给定清零、使能，再设置参数并开始。设备端也检查准入条件，不能靠界面的勾选绕过。完成或中止后清零并失能；下一次测试需要重新使能。

建议先用逐频正弦、小电流和宽频段取得基线；快速多正弦用于定位趋势，再用逐频法复测交点附近。这里的建议是本实现的调试流程，不是任何厂商对本硬件的性能保证。

| 项目 | 实现值 |
|---|---|
| 测量路径 | 限幅前生成 Iq 参考，经现有电流控制器、PWM、电机、采样和滤波，到 `state.i_q` |
| 控制模式 | 只允许已运行、已使能的 CST；不新增正常运动模式、不自动使能 |

| 逐频法 | 对数布点、整周期量化；稳定至少 20 ms 且至少 4 周期；测量 4 段，每段 4 周期 |
| 多正弦 | 50 ms 相干周期，当前为 20 Hz 栅格；1 段稳定、3 段测量，共 200 ms 设备采集时间 |
| 输出 | 实际频率、输入/反馈基波幅值、H1 实虚部、相干性、平均段数 |

## 扫频的作用与参考实现

扫频是在一个稳定工作点附近注入有界的小信号，比较不同频率下的输入和输出，从而得到幅频与相频曲线。它主要用于验证控制带宽、识别共振或反共振、评估滤波和采样延迟，以及比较修改 PID 前后的响应。它本身不是自动整定，也不等同于电阻、电感辨识。

| 参考 | 可核实的机制 | 对本系统的启示与边界 |
|---|---|---|
| ODrive 开源 `Controller::update()` 的 `INPUT_MODE_TUNING` | 按控制周期累加相位，分别产生位置、速度、转矩正弦参考；之后仍经过参考限幅 | 借鉴控制周期同步激励和既有限幅链。该代码段是调试信号源，不能单凭这个模式宣称有完整自动扫频/Bode 估计流程。[源码](https://github.com/odriverobotics/ODrive/blob/master/Firmware/MotorControl/controller.cpp) |
| VESC `mcpwm_foc_measure_inductance()` | 暂时接管驱动、使用 HFI 测量、检查故障，结束时恢复配置并释放控制权 | 借鉴测试的控制权和退出处理。所查代码用于电感辨识，不能当作闭环电流频响测量。本实现不复制其 HFI 或临时改写电机配置的方式。[源码](https://github.com/vedderb/bldc/blob/master/motor/mcpwm_foc.c) |

| Elmo Sine Sweep | 对一组频率注入正弦、记录响应、生成速度/位置对象的 Bode 图，并提供电流和跟踪限制 | 借鉴逐频辨识和运动范围限制。公开页面是功能说明，不能推断其未公开的内部估计算法；本次测的是电流闭环，不是其机械对象辨识。[官方说明](https://www.elmomc.com/capabilities/servo-technology/special-functionality/sine-sweep-emulation/) |

以上是架构和方法参考，没有移植第三方驱动实现，也没有依赖或使用 Elmo 的私有代码。查阅日期为 2026-11-19；GitHub 链接指向公开默认分支，内容可能继续变化。

### 必须区分的三种测量

1. **本次电流闭环**：`Iq_ref → Iq_feedback`，得到包含实际延迟和反馈滤波的闭环传递响应 T。
2. **机械对象**：通常用实际转矩电流作为输入、机械速度或位置作为输出。需要正确的电流/速度采样同步、运动限制，以及明确电流环是否包含在对象内。
3. **开环环路增益**：需要合适的注入位置和多个采集信号。不能将本次 T 的相位直接称为相位裕度，也不能把 `T/(1-T)` 当作无条件可靠的开环测量；控制结构、反馈定义、前馈和测量噪声都影响该推导。

连续 chirp 的优点是扫描快，但瞬时频率变化会引入非稳态和谱估计问题。逐频正弦更容易保证稳定段、整数周期和相位可解释性；多正弦并行激励多个离散谱线，速度快，但总幅值分摊后单频信噪比下降。这是本次保留两种离散测量方法的原因。

## 算法与时序约定

每个采样周期读到反馈 `y[n]`，生成本周期将施加的参考 `x[n]`，按当前正交相位累积输出；周期输入的投影在前台按完全相同的递推顺序预计算。反馈在命令生效之前取得，因此估计自然包含这段因果延迟；不会把 `y[n]` 偷移到 `x[n-1]` 上以美化相位。

各频点先预计算振荡器旋转系数，ISR 中只做固定大小的递推与乘加。输入 X 在各测量段相同，ISR 保存原始 Y 的和与能量，前台按以下等价定义计算结果（归一化、除法、开方均在前台）：

```text
Sxx = Σ |X|²
Syy = Σ |Y|²
Syx = Σ Y·conj(X)
H1  = Syx / Sxx
γ²  = |Syx|² / (Sxx·Syy)
gain_dB = 20·log10(|H1|), phase = arg(H1)
```

相位振荡器在完整段边界复位，限制递推漂移。多正弦使用 Schroeder 初相位，并在前台遍历完整离散周期求合成峰值，归一化后保留 0.1% 余量。输入幅值是各谱线的峰值幅度估计，不是全部谱线的总峰值或 RMS。

稳定段不参与统计。主机按相干性及幅值判断质量；零响应返回零相干性的低质量频点，不能伪造为单位增益。多段相干性反映段间一致性，高相干性仍不能证明完全线性、没有谐波或系统偏差；应结合不同小幅值、重复测量和逐频复测。

现有 MotorTune 以首两个有效低频点的平均增益作为平台，寻找首次相对下降 3 dB 的相邻有效交点，并按对数频率插值。没有交点就报告未测到；不跨越无效点、不外推带宽。两点平坦也不是直流平台的充分证明，需确保扫到了足够低的频段。

## 模块边界与接入点

新增实现全部放在 `project/APP/FOC/sweep/`：

- `sweep_engine.h/.c`：调用者持有上下文；不依赖电机、MCU、CAN、全局单轴或动态内存。管理频点、激励、采样统计和结果。
- `foc_sweep.h/.c`：将算法适配到当前单电机 CST；管理控制权、临界区、保护、DWT 时序和退出。
- `sweep_protocol.h/.c`：封装 v1 协议的解析/序列化；通过回调复用现有 CAN 发送队列。

既有生产文件只改 4 个：

| 文件 | 修改 |
|---|---|
| `FOC/foc.c` | 控制分发边界一次 owner 判断；测试走独立适配器，复用原电流环；普通 PID/调制内没有扫频钩子 |
| `APP/motor.c` | `motor_disarm`、`motor_shutdown` 通知适配器撤销测试 |
| `can_fd_custom.c` | 委托新协议模块，限制单播启动；外部电流目标或 IAP 指令撤销测试 |
| `motor_controller.uvprojx` | 注册三个新 C 文件 |

没有更改 PID 算法、正常控制模式、持久化结构、PWM/ADC 配置、已有 SRAM scatter 文件或原通信命令编号。测试使用独立 Iq 参考，不把每拍激励写入普通 `m->ref.iq`，避免累加注入或覆盖正常命令存储。

默认 `FOC_SWEEP_ENABLED=0`，接入宏成为空操作，扫频上下文不链接；协议返回 error=3（功能未编译）。新增源文件仍可保留在工程。只有全局定义 `FOC_SWEEP_ENABLED=1` 的诊断固件响应合法启动请求；未启动时只有分发处一次 owner 检查，不能声称与编译关闭相同的周期数。正常电流 PID 和调制保持原实现，限幅后由测试适配器拒绝数据并失能。

### 前台与中断的所有权

前台完成所有频点和峰值预计算时保持中断开启，尚不发布测试所有权。随后在短临界区再次检查状态，用内存屏障后发布 owner。只有控制 ISR 修改运行中的统计；状态查询复制一个短快照，只有完成且释放 owner 后才能读结果。开方和序列化在前台执行，不在 ISR 发 CAN，不存储整段 20 kHz 波形。

本适配器基于现有单前台调度；若未来从多个 RTOS 线程同时调用 start/read，必须另加前台互斥。纯算法模块支持多个上下文，不意味着当前适配器已经支持多轴。

## 退出与限制

启动要求：已校准、CST、运行状态、硬件已使能、无瞬时/锁存故障、普通电流给定严格为零；起始电机轴速度不超过 1 rad/s。Iq 幅值须符合表中边界，d/q 电压输出限值有效，d/q PID 输出 ramp 为零。非零 ramp 直接拒绝，避免将斜率限制后的非线性响应当作小信号频响。

测试期间保留全部既有保护，另外检测：

- 实际电流参考与本拍激励不同，包括电流钳位或软限速介入；
- d/q 电压输出触限、积分贡献触限、PWM 电压矢量缩放；
- 非有限反馈、位置、速度或温度，板温/电机温达到 60°C；
- 相对启动点的**电机轴**位移达到 0.5 rad，或轴速达到 5 rad/s；
- 当前 20 kHz 下相邻 FOC 回调开始间隔超出 40–60 μs，或测得回调主体耗时超过 45 μs。

独立测试边界在 `foc_sweep.h` 的 `FOC_SWEEP_MAX_*` 宏中定义，可按具体机构的测试要求调整；不是修改普通运动限值。它们不能替代机械限位。速度值沿用现有外环采样/估算更新节拍，不宣称是每个 PWM 周期独立的新测速。

取消、失能、故障、模式改变、竞争电流命令（含零命令）、IAP 指令都会撤销激励。停止先撤销 owner，再清零并失能；保持故障锁存，不恢复旧非零目标、不自动重新使能。最后一拍仍执行限幅和时序检查，不能因为算法刚采满就提前发布有效结果。

单次测试不需要主机续租。通信中断不会无限维持激励，设备会完成有限测试或由本地保护中止；这也意味着断线本身不是立即停机信号，不能把 CAN 连接状态当硬件急停。

## CAN-FD v1

所有多字节值为大端，浮点为 IEEE754 binary32。长度为去掉 CNT/CMD 后的有效负载，接受 CAN-FD DLC 尾部填充。只接受本节点单播的扫频请求，禁止广播启动。

| 命令 | 请求 | 专用应答 |
|---|---|---|
| `0xBC` 控制 | 11 字节：`version:u8=1, action:u8(0停止/1多正弦/2逐频), run:u16, lowHz:u16, highHz:u16, count:u8, peak_mA:u16` | 下列状态（基础 20 字节，诊断版扩展到 40 字节） |
| `0xBD` 查询 | 空 | `version:u8,error:u8,state:u8,method:u8,run:u16,count:u8,progress:u8,fs:u32,samples:u32,flags:u16,max_us:u16` |
| `0xBE` 读取 | `run:u16,index:u8` | 34 字节：`version:u8,error:u8,run:u16,index:u8,state:u8,flags:u16,hz:f32,input:f32,output:f32,H1real:f32,H1imag:f32,coherence:f32,blocks:u16` |

state：0 空闲，1 采集，2 完成，3 中止。error：0 成功，1 忙/状态或会话不允许，2 参数/数据不合法，3 功能未编译。run 必须非零，读取结果必须匹配当前 run。启动时忙会拒绝，不覆盖运行状态；重复读取完成结果不消耗数据。停止不受 run 匹配限制。

诊断版状态的 20–39 字节包含周期间隔、时序中止原因/样本号、感测/控制/算法峰值耗时及 A5/A6 标记，字段表见 [优化记录](SWEEP_OPTIMIZATION.md#可读出的计时数据)。默认关闭版返回基础 20 字节状态及 error=3，结果帧仍为 34 字节。

flags：`0x01` 停止/状态失效，`0x02` 限制介入，`0x04` 时序异常，`0x08` 竞争命令，`0x10` 测试运动边界，`0x20` 非有限测量。老界面会显示数值 flags，本表给出其含义。原 `0x7E` 分发 ACK 继续保留，不能作为扫频开始成功或完成依据。
