# 失能确认与操作反馈修复

## 状态确认

- 0x40 使能/失能和 0x41 模式切换以发送后的设备遥测确认目标状态。0x7E 只表示分发 ACK，专用成功应答也不单独证明电机状态已改变。
- 延迟到达的上一条命令应答不作为当前操作成功的依据；ACK 需要匹配请求计数器和命令。状态已由新遥测确认时，不再仅因专用应答缺失报操作失败。
- 失能优先发送，撤销尚未执行的同节点运动/模式命令以及等待中的使能/模式事务。点击失能同时停止主机激励和自动测试，避免后续自动指令再次驱动电机。
- 等待期间显示“失能确认中”，超时明确显示“失能未确认”、最近设备状态以及应答情况。遥测超时保留最后实际状态，不把状态强行改成已失能。
- 0x40 仅接受单字节 00/01；其他值在发送前拒绝。

## 可见反馈

全局操作提示条位于顶部控制区下方，在所有页面可见。设备占用、连接失败、运行错误和命令失败持续显示，可展开完整详情或手动关闭；普通日志不会覆盖未关闭的错误。提示不阻挡急停及其他窗口操作。连接失败保留原始原因，不再被随后通用“已断开”消息覆盖。

原生 CAN 接收路径按驱动报告的可用帧数读取，分别查询经典 CAN 与 CAN FD，沿用旧版的接收调用方式。截图反映了应答滞后，但尚未在真机确定该滞后的具体原因。

## 回归范围

新增脚本后端覆盖 V1/V2 延迟前序应答、ACK/成功应答后仍使能、失能抢占等待中的使能、遥测丢失、无效参数和设备占用。窗口测试覆盖跨页面错误可见、错误不被普通消息覆盖、关闭提示及 Demo 失能状态反馈。

保留限速手动策略：每次连接成功自动读取 B5 一次，之后仅点击读取时查询；B6 仅点击发送时下发。无自动轮询或自动重试。保留既有示波器性能优化及多 CAN/协议兼容路径。

自动测试使用 Demo 和模拟后端，未操作真实电机。真实设备仍需复验失能、CAN 盒接收时序和设备占用提示。
