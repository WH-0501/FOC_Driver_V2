# C03：默认速度环积分上限为零的修复

## 1. 问题及原因

本地项目：`D:\workspaces\code-registories\FOC\FOC_Driver_V2\motor_controller`。

`motor_config_set_defaults()` 先将配置清零，随后设置速度环 `ki=0.003`，但未设置 `velocity.i_limit`。PID 每拍结束都将积分状态夹在零范围，无法持续积累消除负载造成的速度稳态误差。原实现还可能将本拍积分增量先加到输出，再清零保存状态，因此并不是语义明确的纯 P 控制。

位置环同样漏设积分上限；默认 Ki=0 时暂不表现，但后续单独调大 Ki 仍无法形成正常积分作用。

## 2. 修改内容

### 默认配置

速度环及位置环显式初始化：

```c
config->pid.velocity.i_limit = config->pid.velocity.limit * DEF_I_LIMIT_FACTOR;
config->pid.position.i_limit = config->pid.position.limit * DEF_I_LIMIT_FACTOR;
```

沿用项目已有 `DEF_I_LIMIT_FACTOR=0.85`，与电流环默认策略一致。四个环现在均显式设置积分上限。

积分上限单位与对应 PID 输出一致：速度环输出为 Iq 参考值，因此速度环上限为 A，不是速度单位。位置环本次只补齐积分上限，沿用其现有输出 limit；原报告 C04 中位置环输出限幅单位问题没有在本次顺带修复，不能认为位置环量纲问题已解决。

### PID 行为

- `i_limit=0`：明确禁用积分，先清除历史积分状态，禁止生成本拍积分增量。
- `i_limit>0`：允许按 Ki 和误差累计积分，并在参与当前输出前限制积分增量形成的积分项；原有输出后的积分兜底限幅仍保留。
- 负值、NaN、无穷大积分上限：返回 `ERR_PARAM`。
- `pid_param_t.i_limit` 注释明确单位及零上限语义，不改变结构布局和存储版本。

没有修改 Ki、控制频率、PWM 最大占空比或硬件采样链路。未扩展 CAN 命令格式；现有仅传 Kp/Ki/Kd 的命令不会自动修改 i_limit。

## 3. 控制原理与影响

\[
I[k]=\operatorname{clip}(I[k-1]+K_i e[k]T_s,-I_{max},I_{max})
\]

速度环比例项只能根据速度误差提供电流。当负载需要持续转矩时，纯比例控制通常需要保留非零误差才能维持相应电流。正确积分可以在误差逐步减小时建立负载所需的电流贡献，并在误差归零后维持它。

本修复恢复默认配置原本表达的 PI 行为，但不代表已经通过实机速度阶跃或稳定性测试。积分现在真正生效后，动态响应与旧固件不同，需在限流条件下复核速度超调、反转和负载突变。

原有反算增益仍硬编码、最终电压限幅反馈仍未贯通，对应 C02/C01，本次没有宣称解决。积分状态限幅不等于所有级联饱和情况下的抗积分饱和已经完善。

## 4. 已保存配置的兼容策略

不自动重写存储配置：旧版本生成的零积分上限与用户主动禁用积分使用相同数据，无法可靠区分。

因此：

- 新默认配置及配置重置获得非零速度积分上限。
- 已加载的 `i_limit=0` 保留，按明确禁用积分处理。
- 希望已有设备启用速度积分时，应显式将 `velocity.i_limit` 设置为与电流能力匹配的正值，并通过现有配置保存接口保存。
- 只有确实需要恢复整套默认配置时才调用配置重置；它还会重置其他调参及校准配置，不应仅为修复一个字段盲目使用。
- 本次未访问或改写硬件 EEPROM/Flash。
