# 电机调试工作台 (CAN / CAN-FD)

本轮改造、性能数据、协议边界与 JustFloat 规划见 [UPGRADE.md](UPGRADE.md)。

基于 CAN/CANFD 协议的 FOC 电机调试 GUI，支持 ZQWL-UCANFD-100E、创芯科技 USBCAN-FD 等周立功 `zlgcan.dll` 兼容 CAN 盒，以及 SLCAN / PCAN 适配器。

## 环境要求

- Python 3.10+
- Windows 10/11（厂商 DLL）或 Linux（SocketCAN）；macOS 尚未验证
- 64 位 Python 需配 64 位 `zlgcan.dll`，仅 Windows 厂商后端需要
- USB-CANFD 驱动（ZCANPRO、USB_CANFD Tool 或创芯 CANFDToolPro）

## 安装

```bash
cd motor_controller_gui
pip install -r requirements.txt
```

## 启动

```bash
python motor_gui.py
```

## 使用流程

### 1. 连接 CAN 设备

1. 选择 **CAN 卡型号**（创芯选「创芯科技 USBCAN-FD (200U)」，ZQWL 选「ZQWL-UCANFD-100E」）
2. 点击 **扫描设备**，选择正确 **索引**
3. 点击 **打开设备**
4. 点击 **CAN0 启动**

> 使用前请关闭原厂 CANFDToolPro / USB_CANFD / ZCANPRO 上位机，避免占用设备。

**驱动文件：** 将 64 位 `zlgcan.dll` 及 `kerneldlls` 文件夹放到 `library/` 目录。

| 型号 | 说明 |
|------|------|
| ZQWL-UCANFD-100E | 周立功 USBCANFD-100U（类型 42），单通道 |
| 创芯科技 USBCAN-FD (200U) | CANFDToolPro 型号 `USBCANFD` / `USBCANFD-200U`（类型 41），双通道 |

**与 CANFDToolPro 通道参数对应关系（本上位机内置，无需手动设置）：**

| CANFDToolPro 参数 | 本上位机设置 |
|-------------------|-------------|
| CAN 卡型号 USBCANFD | 设备类型 41（200U） |
| 索引 0 | 扫描/打开时选择索引 0 |
| 工作模式：正常 | `InitCAN.mode = 0` |
| CANFD 标准：ISO | `canfd_standard = 0` |
| 仲裁域 1 Mbps (80%) | `canfd_abit_baud_rate = 1000000` |
| 数据域 5 Mbps (75%) | `canfd_dbit_baud_rate = 5000000` |
| 启用滤波：未勾选 | 不配置滤波；双通道 USBCANFD 使用合并接收 |
| 终端电阻 | 默认开启（`initenal_resistance = 1`） |

**通道如何选择：**

| CANFDToolPro | 本上位机下拉框 | API 索引 |
|--------------|----------------|----------|
| 通道 1 | 通道1 (API CAN0) | 0 |
| 通道 2 | 通道2 (API CAN1) | 1 |

打开设备后，在「**CAN 通道**」下拉框选择电机所接物理口，再点 **启动**。单通道 ZQWL 仅显示通道 1。
| SLCAN 适配器 | CANable 等，需选择串口 |
| PCAN-USB | Peak CAN 接口 |

### 2. 添加电机

- 在 **电机管理** 中输入 ID，点击 **添加电机**
- 或点击 **扫描在线电机 (1-21)** 自动发现

### 3. 电机示波器

支持时域、FFT、XY、直方图、条形图、双游标、min/max/mean/RMS 和原始 CSV 导出。
缓存可选 1 万 / 12 万 / 100 万点；绘图采用保峰值降采样，采集与显示分离。

- **冻结显示**：停止刷新并保留历史快照，后台继续采集；拖动和缩放查看历史。
- **滚轮缩放**：实时模式下继续刷新，保留缩放尺度；拖动查看历史才冻结。
- **实时跟随**：恢复到最新窗口；**重置视图**恢复 6 秒及自动 Y 轴。
- **采集**：单独控制是否写入缓存；清空只清当前电机。
- **Y / 测量**：选择 FFT、统计和游标 Δy 通道；XY 可独立选 X 通道。
- **FFT**：选择点数，正确设置设备采样间隔（默认 1 ms），频率标定依赖此设置。
- **连接与设备菜单**：打开连接设置窗口，并提供打开设备、启停通道、关闭设备及设备信息入口。**视图菜单**保留日志面板显示控制。

旧固件没有 Id/Ia/Ib/Ic 时对应曲线留空。经典 CAN 仅支持不超过 8B 的原协议短命令，
原周期遥测需要 CAN-FD；不能将适配器兼容理解为完整固件协议兼容。详见 [UPGRADE.md](UPGRADE.md)。

### 4. 运动控制（右侧面板）

### 电流阶跃分析（扭矩模式）

在扭矩模式采集含目标 Iq 变化和实际 Iq 的数据，点击示波器的 **电流阶跃分析**。
窗口分析当前电机完整缓存的快照；冻结显示时使用冻结快照，不限于当前缩放范围。
它不发送电机指令，也不会自动改变控制模式。请确认记录对应扭矩模式。
关闭后重新打开可分析最新数据；修改设置后需点击“分析 / 重新计算”。

| 功能 | 计算及显示规则 |
|---|---|
| 阶跃识别 | 按目标 Iq 变化分段，默认最小幅值10mA；任何后续目标变化都会截断当前响应。阶跃前至少5点，最多20点取中位数作为实际初值。 |
| 上升时间 | 从实际初值到目标的方向归一化10%～90%交越间隔，采用线性插值；支持下降、反向及非零初值。交越未完整捕获则留空。 |
| 超调 | 沿阶跃方向超出目标的最大偏差 / 实际初值到目标的幅值；单调响应为0。 |
| 调节时间 | 从目标变化首个遥测点，到末段持续在误差带内的起点；该末段须至少保持设置时长（默认5ms）。未满足则留空，不记为0。 |
| 调节误差带 | 默认 max(5mA, 目标绝对值×2%)；可改用阶跃幅值归一化，并可调整绝对下限。 |
| 振荡次数 | 首次显著超调后的交替正负波瓣，两瓣计一周期，末尾半周期向上取整。噪声门限取设置值与阶跃前峰峰噪声一半的较大者。 |
| 振荡幅值 | 首次超调波瓣之后的最大绝对偏差，显示mA及选定基准下的百分比；目标为0且按目标归一化时百分比留空。 |
| 统计/导出 | 每次阶跃明细，各指标可用数量、均值和最大值；CSV含电机ID、分析设置、参考上限、明细及汇总。缺失值不计入统计。 |

参考上限默认上升1.5ms、超调5%、调节5ms、振荡3次及振荡幅值5%，均可调整；
这些是界面的初始参考值，不代表该电机已经确认的验收要求。
分析标记初始未稳态、采样不均匀、上升段采样不足及观察时间不足。
均值/最大值包含低分辨率估算；只有超限提示，没有“验收合格”结论。

**时间与数据限制：** 当前目标是上位机命令记录，不是设备确认的生效参考；
时间轴来自既有遥测缓存（缺失或异常时间戳时原缓存会用1ms补时），不是FOC高速采样时间。
命令和排队遥测之间还可能存在传输/处理时差；不应用结果直接验收亚毫秒电流环。
插值不能恢复漏掉的峰值和振荡；FFT采样间隔设置不改变本分析的时间轴。
需要精确验收时，应使用设备同步记录的生效参考、实际电流和采样时间戳。

## 协议说明

- 帧格式：`[CNT, CMD, DATA...]`，Node-ID 在 CAN 仲裁段
- 周期上报：位置(Q7)、速度、Iq(mA)、状态、错误码；新版另含 Id/Ia/Ib/Ic（见下表）

| 固件版本 | CAN FD DLC | 有效 payload | 字段 |
|----------|------------|--------------|------|
| 旧版 | 12 | 8B (+0 填充) | pos, vel, iq, status, error |
| 新版 | 20 | 16B (+0 填充) | pos, vel, iq, id, ia, ib, ic, status, error |

上位机按 payload 长度与尾部填充自动识别格式，无需手动切换。
- 默认 CAN FD：仲裁段 1Mbps，数据段 5Mbps

## 常见问题

**扫描不到设备**
- 确认 DLL 位数与 Python 一致（64 位对 64 位）
- 关闭原厂上位机
- 检查 USB 连接与驱动

**打开成功但无法启动通道**
- 确保先 **打开设备** 再 **启动 CAN0**
- 检查 `kerneldlls` 是否完整

**波形不更新**
- 确认 CAN 通道已启动
- 勾选 **数据采集**
- 电机需在线并周期上报

## IAP 固件升级

遵循 `motor_controller/docs/CAN-FD通信协议.md` 与 dex-con `iap.c`：

1. **FD** 读固件版本
2. **F8 ENTER**（Node-ID，无应答，state: IDLE→READY）
3. **F9 START**（ASIX 32B 头 + 首段数据，载荷 >32B；从机**同步擦除** Flash）
4. **等待 FC**（`state=2 接收中, error=0x80`；iap.c 注释「应答后才开始下一帧接收」）
5. **FA DATA**（帧计数从 2 递增，62B/帧，末帧 0xFF 补齐）→ **FB END** → **FE VERIFY** → **FF RESET**

注意：
- 固件 `IAP_TIMEOUT=3000ms` **从 START 进入起算且含擦除时间**；FC 到达后剩余窗口通常仅数百 ms，须**立即连发 DATA**。
- ENTER+START 使用 ZCAN 批量提交；发送/接收分锁，避免周期上报阻塞 IAP。
- IAP 关键帧日志异步输出，避免 Qt 阻塞 CAN。

### 指令响应与遥测积压诊断

- 发送日志中的“发送调用耗时”包含发送锁等待和驱动调用；驱动返回成功不等于电机已经执行。
- 状态栏显示接收队列数量、最旧帧等待时间、过载/过期丢帧及最近发送调用耗时。
- 遥测按小批次处理，每轮约4ms预算（在64帧批次边界检查），让按钮和命令应答及时获得事件处理机会。
- 实时显示会丢弃在上位机队列等待超过250ms的遥测并累加丢帧计数；此时缓存/CSV不再是完整采样记录，不能用于精确阶跃验收。协议应答不经过该过期丢弃路径。
- 目标曲线按遥测进入上位机接收线程的时刻匹配，不再把新目标套到此前已收到但尚未绘制的旧反馈上。驱动内部积压、USB延迟及设备执行时间仍不在此时间基准的保证范围内。
- 若发送调用很快、队列时间也很小，但电机仍明显迟动，应结合CAN抓包检查驱动内部队列、总线及固件执行；不能仅根据目标曲线与反馈的间距判断发送延迟。

### 单播设备应答诊断

运动控制固定使用当前Node-ID单播：使能、失能、模式、位置/速度/电流目标及同步均不再提供广播切换。校准页设原点也只作用于当前电机。批量面板只对勾选电机逐台单播，不使用广播地址。
新版固件对0x40/0x41返回操作结果，并对普通单播命令追加0x7E处理确认。
日志中的“发送调用耗时”仅到驱动返回；“设备处理确认…往返=…ms”按原请求CNT/CMD匹配，包含发送、设备排队/处理、回复及上位机事件处理时间。
0x7E不是动作成功或电流收敛证明，成功/拒绝原因看专用应答。超过30s未确认只提示，不自动重发使能等命令。
旧固件不支持0x7E时会提示确认超时，但原控制指令仍可能已经执行；需同步更新固件。广播没有逐机RTT。

### 通用阶跃响应分析（更新）

示波器入口现为“阶跃响应分析”，可切换电流Iq、速度、位置，分别使用目标Iq/实际Iq、目标速度/实际速度、目标位置/实际位置。
单位为mA、RPM及当前协议的rad或°；位置值不自动解绕，跨角度回绕的记录应先确认其连续性。位置/速度的响应包含内环、机械负载及参考处理，不能当作独立内环性能。

- 每次阶跃观察窗可设置，0表示一直到下一条目标变化或缓存结束。初始建议窗口分别为电流100ms、速度1000ms、位置2000ms，均可修改，不是验收时间要求。
- 10%/90%交越默认须在阈值以上保持2ms，抵抗单点尖峰；设0可恢复原首次交越方式。它不能恢复采样遗漏的动态过程。
- 超调明确标记为“原始峰值超调”，不做平滑或删除尖峰；交替波动计数包含扰动，不代表欠阻尼振铃次数。不同观察窗的统计不能直接比较。
- 新增末段均值、相对目标的有符号偏差和峰峰值，采用观察窗最后20%且至少5点；这不是已确认稳态。
- 位置/速度默认按阶跃幅值定义相对误差带，参考上限默认0（不检查），避免沿用电流环的毫秒级阈值。切换通道会重置该通道的初始分析参数，需重新确认设置。
- CSV记录所选通道、单位、观察窗、交越保持、阈值及明细；保留既有内部字段名的兼容性，带_ma的内部键在通用分析中表示当前选定单位。

### 菜单与布局

- “连接与设备 → 连接设置…”打开非模态设置窗口，关闭设置窗口不会断开连接。菜单快捷操作沿用面板的启用状态及连接逻辑。
- “分析 → 阶跃响应分析…”打开当前电机的通用阶跃分析，后续分析功能统一放在此菜单。
- Node-ID选择和“扫描在线(1–21)”位于菜单栏右侧，原电机管理整行及波形区域的阶跃分析按钮已移除。
