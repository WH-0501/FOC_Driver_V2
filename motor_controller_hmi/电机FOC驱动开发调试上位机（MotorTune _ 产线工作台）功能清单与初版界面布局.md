# 电机FOC驱动开发调试上位机（MotorTune / 产线工作台）功能清单与初版界面布局

# 一、文档说明

本文档依据三份输入整理而成：

1. **CAN\-FD通信协议\.md**（协议版本 V2\.0\.0，当前 motor\_controller FOC 固件）：提供帧格式、CMD 命令表、周期上报 18B 布局、IAP 流程、单播确认机制等协议事实。

2. **出厂测试及上位机需求分析\.xlsx**（四个工作表：上位机功能需求、出厂标定项、出厂测试项、SN参数库表单）：提供研发/产线双入口需求、8 步产线标定流程、31 个出厂测试用例、SQLite 归档表结构。

# 三、完整功能清单

## 3\.1 公共底座（两入口共用）

### 3\.1\.1 通信协议引擎（CAN\-FD 链路）

**物理层与帧格式**

- ISO\-CAN FD \+ BRS，仲裁段 1Mbps、数据段 5Mbps。

- 帧结构：Node ID（仲裁段）\+ CNT（帧计数）\+ CMD（功能码）\+ DATA \+ 协议填充（0x00）；DLC 档位 0\~8、12、16、20、24、32、48、64。

- ID 过滤：电机端正常只收 0x00（广播）、自身 ID、IAP 的 0x7FF；0x00 表示广播。

- 协议版本 V1\.0\.0 / V2\.0\.0 显式选择，不可混用；差异在位置 Q7 单位（rad / °）、0x41 控制模式线值、状态字节高低位语义、周期上报 8B/18B、PID Q12、error 字节解析。

**主机 → 从机命令表（CMD 全表）**

|CMD|功能|关键语义|
|---|---|---|
|0x00|同步信号|同步所有关节周期上报时间，不应答|
|0x01|目标位置|id\+pos，Q7，V2 单位 rad（1 LSB=1/128 rad）|
|0x02|目标速度|id\+vel，Q0 short（RPM）；DHB1 减速端速度 Q7|
|0x03|目标电流（力矩）|id\+cur，Q0 short，单位 mA|
|0x12 / 0x13 / 0x23|位置\+速度 / 位置\+电流 / 速度\+电流|组合指令，单帧多电机（电机数 × N 字节）|
|0x30|位置\+速度\+电流|单帧最多 8 电机，多帧周期下发（首帧含总帧数\+帧序号）|
|0x39|异常复位|强制关断、清故障、清零给定回 IDLE；应答 1B error\_t|
|0x40|使能 / 失能|0=失能 1=使能；单播应答同 CMD \+ error\_t；V2 须先 0x41 设模式|
|0x41|控制模式|V2 control\_mode\_t：0 IDLE、1 TORQUE、2 SPEED、3 POSITION、4 CSP、5 CSV、6 CST、7 MIT、8 HOMING、9\~11 开环、12 VOLTAGE；须失能后设置，运行中切换返回 ERR\_STATE|
|0x42 / 0x43 / 0x44|设置位置 / 速度 / 电流环 PID|失能有效；P/I/D 各 2B uint16 大端，K=raw/4096；电流环 I 为缩放 Ki（Ki\_phys/10000）|
|0x45|设置刚度 / 阻尼|失能有效；各 2B uint16，K=raw/4096|
|0x46|设置保护参数|失能有效；过温/过流各 2B，欠压/过压各 1B|
|0x47 \~ 0x4B|获取三环 PID / 刚度阻尼 / 保护参数|只读回传，格式同对应 Set 命令|
|0x4C|设置 Node ID|保存后可用；应答修改后 ID|
|0x4D|保存设置|失能有效；写用户区 Flash|
|0x4E|恢复全参数出厂|失能有效；整份 motor\_config 恢复默认并写 Flash|
|0x4F|清除锁存故障|清 fault\.latched 回 IDLE；应答 error\_t（25=无锁存故障）|
|0x50|设置原点|失能有效；当前位置设为零点|
|0x52|获取电机类型|0=HC14、1=HC12、2=HR14、3=HR12|
|0x53|电机本体只读参数|应答 16B：极对数、方向、减速比\(×1000\)、电角零偏、机械零偏、编码器 CPR、对齐标志|
|0x54|仅恢复三环 PID 出厂|仅 config\.pid 恢复默认；保留电角、本体参数、保护、Node\-ID|
|0x7F|周期上报频率|0\~1000Hz，0 停止，超 1000 无效；上电默认 1000Hz|
|0xAB|电角度对齐|单播、失能有效；方案 0 Ud、1 Uq、2 Ud 双点、3 Uq 双点、4 HFI；应答 14B（error\_t\+方案\+方向\+标志\+电角\+零偏\+极性探针 Iq）|
|0xAC|MCU 温度校准|失能有效；单位 0\.01℃|
|0xAD \~ 0xB0|KTH71 芯片校准（ANLC）|0xAD 进入校准会话（须已使能）、0xAE 查询自校准状态（0 未开始/1 校准中/2 失败/3 完成）、0xAF 停止校准、0xB0 触发芯片 ANLC|
|0x7E|单播处理确认|非 IAP 且非应答专用命令单播时追加；2B：原请求 CNT \+ 原请求 CMD；仅确认分发完成，不代表动作成功|
|0xF8 \~ 0xFF|IAP 升级|0xF8 ENTER、0xF9 START、0xFA DATA、0xFB END、0xFC 查询状态、0xFD 查询版本、0xFE VERIFY、0xFF RESET；广播 ID 0x7FF 或指定 Node|

**从机 → 主机：V2 周期上报（18B DATA，DLC=20）**

|偏移|长度|字段|说明|
|---|---|---|---|
|0|2|pos|Q7 rad，raw/128，控制系关节角|
|2|2|vel|关节端转速 RPM（int16 大端）|
|4|2|Iq|mA|
|6|2|Id|mA|
|8|2|Ia|mA|
|10|2|Ib|mA|
|12|2|Ic|mA|
|14|1|status|高 4 位使能（非 0=使能）；低 4 位 control\_mode\_t|
|15|1|error|V2 故障压缩码（BIT7=0 保护 / BIT7=1 IAP）|
|16|1|MCU 温度|整数 ℃|
|17|1|母线电压|0\.1V/LSB|

**IAP 要点**：升级包带 32B ASIX 头（Signature='ASIX'、ImageType=3、FileLen 大端、Checksum32 小端）；状态机 IDLE→READY→RECEIVING→VERIFYING→COMPLETE/ERROR；帧超时 3s；错误码表含 Flash 擦写/验证、CRC、超时、丢帧等。升级中固件失能电机、停止周期上报、丢弃控制帧，上位机示波应暂停并明确提示 IAP 模式。

### 3\.1\.2 安全门禁

- 急停在研发/产线任何页面常驻可用，独立高优先级发送通道。

- 写 Flash（0x4D/0x4E/0x54）、改零点（0x50/0xAB）、改机型、改 Node ID（0x4C）、电零、SetOrigin 均必须失能；使能中下发被固件拒绝（如 SaveParam、SetNodeId、RestoreFactory、SetOrigin、SetMotorType、TemperatureAlign、HoldStall 写入等，见出厂测试 AT\-CFG\-02\~11）。

- 转轴类步骤（齿槽、磁链拖速、启动电流、Motion 短测等）开始前确认空载未堵转；产线向导强制勾选，研发入口警告。

- 危险参数（硬限流、保护阈值）修改二次确认；急停后 enable=0 且 Iq/Vel/Pos 给定清零。

### 3\.1\.3 CAN 盒兼容性（抽象后端）

- 同一套应用兼容两类 USB CAN FD 设备：周立功 USBCANFD 系列、创芯科技 CAN 分析仪（型号实现前固化并写入发布说明）。

- 架构：抽象 CanBackend 接口（打开/关闭/发 FD 帧/收 FD 帧/枚举设备），周立功与创芯各一实现；上层 CanBusService/Session 只依赖抽象接口。

- 连接前可选「自动」或手动指定后端；自动按优先级探测并显示厂商/型号/通道；同时仅打开一只盒子；切换厂商须先关闭当前连接；状态栏标明当前后端。

- 驱动/DLL 随安装包部署；缺驱动明确报错（厂商名\+缺失项），禁止静默失败；能力对等（遥测、应答、扫描、IAP、产线标定/测试路径在两盒上行为一致）。

### 3\.1\.4 软件安装向导与版本号

- Windows 安装向导：选安装目录、默认角色（研发/产线）、产线锁定选项、两类 CAN 盒依赖检测（允许只装一种）、快捷方式、安装日志；升级覆盖安装保留用户配置（Node、窗口布局等）。

- 版本号语义化 MAJOR\.MINOR\.PATCH（可附 \+build/短哈希），编译期注入；展示于标题栏/状态栏常显、About 对话框（含构建时间、Qt 版本）、SQLite app\_version 字段、出厂报告页眉；协议/schema 变更时递增并在发布说明标注最低兼容固件版本。

### 3\.1\.5 插件扩展与Python API（核心扩展能力）

**设计理念**：参考VOFA\+插件生态架构，剥离固化功能，构建可扩展的上位机能力边界，核心功能原生内置、拓展功能插件化部署，同时提供带安全门禁的Python脚本API，支持用户自定义数据分析、波形解析、测试流程开发，兼顾灵活性与设备安全性。

- **插件基础架构**插件热加载机制：支持动态加载/卸载自定义插件，无需重启上位机，不影响核心调试、标定、测试功能运行。

- 标准化插件接口：预留**自定义波形解析器**、**自定义数据分析面板**、**自定义自动化测试流程**三类核心接口，支持第三方拓展功能开发（如自定义滤波算法、专属电机分析模型、定制产线测试用例）。

- 原生功能插件化：Bode图、高阶频谱分析、自定义报表等非刚需核心功能改为插件部署，精简主程序体积，提升运行稳定性。

**Python 脚本API能力（带安全门禁）**只读开放接口：支持脚本读取电机实时遥测数据、参数配置、波形原始数据、测试日志、标定记录，用于自定义数据分析、批量数据导出、算法验证。

受限控制接口：仅开放失能状态下的参数读取、参数保存、日志查询、设备状态查询，**严格禁止插件/脚本绕过安全门禁下发电机使能、运动指令、Flash写入、参数修改等高危操作**，从架构层面杜绝安全风险。

脚本运行机制：内置沙箱运行环境，支持单脚本手动执行、批量脚本自动化运行、测试流程脚本联动，适配研发批量调参、产线定制化测试场景。

**安全与权限管控**权限分级：核心安全操作（电机运动、写Flash、参数修改）仅主程序原生入口可执行，插件/脚本无最高权限。

操作审计：所有插件、Python脚本的操作行为自动记录日志，包含调用时间、接口、操作内容，可追溯核查。

异常隔离：插件崩溃、脚本报错不会导致主程序闪退、CAN链路中断、设备失控，具备独立异常捕获与隔离机制。

**适配场景**：研发自定义FOC算法验证、批量电机参数标定自动化、产线定制化测试流程开发、第三方工具生态对接、用户专属数据分析模型拓展。

## 3\.5 待确认与风险项（实现前必须与固件对齐）

1. **CMD 编号冲突（最重要）**：需求分析表与协议文档 V2\.0\.0 对若干命令的编号不一致——需求表「0x51 写机型」在协议文档中不存在（0x52 为获取电机类型）；需求表「HoldStall 经 0x53 写入、0x54 读回」在协议文档中 0x53 为电机本体只读参数、0x54 为仅恢复三环 PID 出厂；需求表「齿槽 0xAE Start/Status」在协议文档中 0xAE 为 KTH71 查询自校准状态。建议以协议文档 V2\.0\.0 为准，向固件确认齿槽补偿、HoldStall、写机型的真实命令映射后固化到协议表。

2. **电阻/电感/磁链辨识暂无 CAN 入口**：需求表注明「现无 CAN 命令进入 FOC\_STATE\_CAILB，上位机也不能点选；产线版需新增入口」，需固件侧补充辨识启动、进度、结果查询命令。

3. **协议版本混用风险**：V1 与 V2 的 0x41 模式线值、位置单位、周期上报长度、error 编码均不同，对 V2 设备发 V1 模式字会导致停机或模式错误；连接面板必须显式选版本并提示。

4. **0x7E 确认语义**：只确认请求走完分发，不代表动作成功；操作结果须读专用应答，UI 不得凭 0x7E 判断成功。

5. **多轴并行示波**：一期可为快速切换\+单轴控制，多轴并行示波列为增强。

6. **KTH71 校准与齿槽补偿入口混淆**：UI 中「齿槽补偿」与「KTH71 校准」两个模块命令域需严格区分，防止误发。
