# 电角度对齐分析与修复

日期：2026-10-28

## 结论与适用范围

截图采用 Ud 单点对齐，速度开环目标为 10 RPM，反馈为 -345 RPM。原 Ud 流程用尚未对齐的 Iq 符号判定编码器方向，并在吸合检查移动转子后自动给零点加 π，不能可靠建立编码器与定子磁场的关系。本次修改重建 Ud 对齐流程，以正反扫角位移判方向、检查配置的极对数，并在两个非对径位置验证跟随关系。

修改对象为原工程 `motor_controller/project/APP/FOC/foc_calibration.c`，不是工作区 `analysis_output/source` 中的旧副本。实际烧录版本尚未核对，因此不能仅凭源码认定截图来自哪次构建。

Uq 单点、Ud/Uq 双点及 HFI 的方向判断和物理标定算法不在本次重写范围内，不能将 Ud 测试结果用于证明这些模式正确。公共的指针、环形计算、提交和失败回滚修复会作用于这些入口。

## 参考流程与坐标定义

[SimpleFOC FOC workflow](https://docs.simplefoc.com/foc_implementation) 将编码器方向、极对数、电角零点和电流采样相序分别检查。本项目不直接复制其锁定角常量，而是根据本项目的 Park/逆 Park 定义推导零点。

项目中 `encoder.c` 已将 direction 施加到机械角和速度，电角计算为：

```text
theta_elec = normalize(pole_pairs × shaft.angle_rad − offset)
```

因此，纯正 Ud 在 theta_open 锁定且方向已验证后，可以使用：

```text
offset = normalize(pole_pairs × shaft.angle_rad − theta_open)
```

不能再次给电角乘 direction。电流采样极性也不能作为编码器方向的替代证据。

## 原实现的问题

| 问题 | 原因与影响 | 本次处理 |
|---|---|---|
| 以 Iq 符号翻转 direction | 电压用开环角，电流变换用未校准的编码器角，Iq 混入未知零点偏差 | Ud 改用正反扫角位移 |
| 吸合检查后自动给 offset 加 π | 转子已被主动移至 theta_open+π，提交时却按原位置判断 | Ud 使用 π/2 验证点并返回；删除公共自动加 π |
| 校验传入 &ctx | ctx 本身已是指针，形成错误的二级指针 | 改传 ctx |
| 环形误差使用 abs(normalize(delta)) | 微小负误差变成接近 2π | 使用有符号最短角差 |
| 直接平均跨零点电角 | 0 与 2π 附近的值被平均到 π 附近；旧 spread 可能为负 | 电角先归一化，以首样本为参考求最短角差后平均 |
| 双点 offset 算术平均 | 例如 0.01 与 2π−0.01 得到错误中点 | 使用最短圆弧中点 |
| 成功判据弱 | 小探针电流被判成功，吸合失败不阻断，缺少极对数检查 | Ud 以实际位移、稳定度和异地回位误差为成功条件 |
| 失败损坏旧参数 | 准备阶段清零 offset，过程可能修改 direction | 保存旧参数；失败恢复，并清除本次成功标志 |

## 新 Ud 流程

1. 验证基本参数，保存原 direction 与 offset；未知方向先临时采用 CW。
2. 在 theta_open 施加纯 Ud，等待稳定并采样；不叠加 Uq。
3. 缓慢正扫一个电周期，再反扫一个电周期。每段分 360 步；默认步间隔为 5 ms。
4. 对每步机械角差解回绕并累计。正反位移必须异号，各段位移绝对值应接近 `2π/pole_pairs`，相对误差不得超过 15%。这只是对配置极对数的检查，不自动修改极对数。
5. 若正扫时控制坐标机械角递减，翻转 direction；随后重新锁定、采样。
6. 缓慢移动到 theta_open+π/2，检查测得电角位移；再缓慢返回 theta_open，检查回位误差。两项均使用 `rotor_engage_tol_rad`，默认 0.35 rad。
7. 在返回点重新稳定采样，计算 offset；提交后用最短角差验证电角，保留原有 0.5 rad 提交容差。
8. 成功置位；失败恢复旧 direction、offset，清除成功状态并上报对齐故障。退出时撤去电压并失能。

锁定采样继续采用 16 点、5 ms 间隔，默认允许电角分散度 0.09 rad。每次扫角结束还等待锁定稳定。默认过程约十余秒，较旧的单点探针流程更长，会发生可见的轴运动。上述阈值需要结合实机摩擦、负载和编码器噪声验证。

`align_polarity_test_iq` 在新 Ud 流程中置 0，表示本方法不执行电流极性探针，不代表采样链路已通过电流极性校验。`align_raw_engage_rad` 现在记录 π/2 验证点；上位机若解释该诊断字段，需按新语义处理。

## 速度异常的独立排查

旧副本的 CAN 反馈编码会把关节 RPM 再乘宏 `GEAR_RATIO=50`；原工程当前实现已经去掉这一乘法，目标与反馈统一为关节端 RPM。本次没有重复修改速度协议。

默认减速比为 50，因此关节目标 10 RPM 对应电机轴约 500 RPM。若使用旧反馈编码，显示 -345 RPM 对应关节约 -6.9 RPM；这只是按旧协议换算的解释，不能证明电机真实转速，也不能解释剩余幅值误差。

Ud 校准修正的是编码器方向和电角零点，速度开环仍不保证转子严格跟随旋转磁场。烧录版本、运行时减速比/极对数、开环加速和负载需要另外核对。

## 验证结果

- MSVC 编译模拟回归程序，开启 `/W3 /WX`；模拟硬件并执行实际修改后的整个校准 C 源码。
- 16 组组合通过：编码器正反方向、初始方向正反、实际极对数 1/3/5/7。检查最终方向、offset、成功标志及失能状态。
- 转子不动、配置极对数错误、采样周期为零测试通过；失败时旧 offset 和 direction 保留。
- 跨零点锁定平均、圆弧中点和微小负角误差测试通过。
- 按现有 Keil 工程包含路径和宏完整编译并链接：58 个 ARM 目标文件通过。校准文件保留其他模式电流极性条件中的两处常量分支不可达警告，不影响链接。

测试模拟的是理想角度跟随，不覆盖电流采样硬件、机械惯性、失步瞬态、实际供电及编码器通信故障。没有执行烧录或实机旋转验证。

回归入口为 `tests/run_electrical_alignment_tests.py`。需要 Visual Studio 2022 Build Tools；可指定 `--root`、`--source` 和 `--build-dir`。受执行环境限制时可用 `--compile-only`，再运行生成的 `test.exe`。

## 实机验收

1. 确认所烧录固件包含本次修改，检查运行时极对数和减速比；在允许扫角运动的条件下执行 Ud 对齐。
2. 重复对齐，确认 direction 一致，offset 的圆周差稳定。失败时检查电压、负载和编码器，不应将失败强制改成成功。
3. 先用低速正反开环指令核对实际转向和反馈符号；明确观察的是电机轴还是关节轴。
4. 核对目标与反馈采用同一侧的 RPM，再检查稳定速度和失步；默认减速比下，关节 10 RPM 对应电机轴 500 RPM。
5. 电流采样相序与极性需要独立验证，完成后再验收电流及速度闭环。
